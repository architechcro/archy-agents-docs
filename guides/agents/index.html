    Agents¶

    An agent is a stored configuration that Archy turns into a reasoning-and-acting (ReAct) agent at run time. It reads the conversation, optionally retrieves from a knowledge base, calls tools and answers.

    flowchart LR
    CFG[Agent config] --> RT[Agent runtime]
    MODEL[Resolved model] --> RT
    KB[Knowledge base] --> RT
    MCP[MCP tools] --> RT
    SK[Skills] --> RT
    MEM[Memory] --> RT
    RT --> OUT[Answer, tool calls, session history]

    Create an agent¶

    Project agents live in /api/v1/orgs/{org_id}/projects/{project_id}/agents. Organization agents live in /api/v1/orgs/{org_id}/agents and are visible from every project of the organization.

    BASE="$ARCHY_API_URL/api/v1/orgs/$ORG_ID/projects/$PROJECT_ID"

curl -s -X POST "$BASE/agents" \
  -H "Authorization: Bearer $ARCHY_TOKEN" -H "Content-Type: application/json" \
  -d '{
    "name": "support-assistant",
    "description": "Answers support questions",
    "config": {
      "sys_prompt": "You are a support assistant. Answer from the knowledge base and say when you do not know.",
      "knowledge_base_id": "7da160d1-8924-4b11-8442-6bd722deccc8",
      "knowledge_base_top_k": 4,
      "temperature": 0.2,
      "memory": {"mode": "buffer", "window_messages": 20}
    }
  }'

    {
  "id": "26fc2a0e-afe5-4c01-849b-eac03777464e",
  "org_id": "84eab6dd-2cc1-41d9-a5e7-0c5e38197865",
  "scope": "project",
  "project_id": "f834cf48-7bf7-4489-8b4b-9c7d8c832cb5",
  "name": "support-assistant",
  "description": "Answers support questions",
  "type": null,
  "config": {"sys_prompt": "...", "knowledge_base_id": "...", "knowledge_base_top_k": 4, "temperature": 0.2, "memory": {"mode": "buffer"}},
  "avatar_path": null,
  "created_at": "2026-11-17T09:19:16.984748",
  "updated_at": "2026-11-17T09:19:16.984750"
}
    Field Meaning
    name Required, 1 to 255 characters
    description Optional text
    type Optional label, up to 50 characters
    config The runtime configuration, described below

    Manage agents¶

    Action Request
    List GET .../agents
    Get GET .../agents/{agent_id}
    Update PUT .../agents/{agent_id}
    Delete DELETE .../agents/{agent_id} (returns {"status": "deleted"})

    Stored config

    Default values are not stored: for example "window_messages": 20 is dropped from a memory object. If the operator configured a default agent model, config.model is filled in when you omit it.

    PUT replaces config

    An update with a config object replaces the whole configuration; it is not merged. Read the agent first, change what you need and send the complete object. Fields you omit at the top level (name, description, type) are left unchanged.

    The configuration¶

    The config object is validated when you save it. An unknown key or a wrong type returns 400:

    {
  "detail": {
    "message": "Invalid config",
    "errors": [{"type": "extra_forbidden", "loc": ["bogus"], "msg": "Extra inputs are not permitted"}]
  }
}

    Core¶

    Key Type Meaning
    sys_prompt string The system prompt. Aliases instructions and system_prompt are accepted. Default: You are a helpful assistant.
    model object {provider, model_name, credential_id}. See Which model runs. Prefer attachments over this field.
    temperature number 0 to 2 Sampling temperature
    top_p number 0 to 1 Nucleus sampling
    max_tokens integer ≥ 1 Maximum tokens of one model reply
    max_iters integer 1 to 100 Maximum reasoning and tool iterations per reply
    token_budget integer ≥ 1 Overall token budget of one reply
    input_token_weight, output_token_weight number ≥ 0 Weights used when counting against the budget

    Knowledge and tools¶

    Key Type Meaning
    knowledge_base_id UUID Knowledge base used for retrieval
    knowledge_base_top_k integer ≥ 1 Chunks retrieved per question
    tools_enabled list of strings Stored tool labels. They are not used by the agent runtime; retrieval is driven by knowledge_base_id.
    skills_enabled list of strings Skills to attach
    automatic_mcp boolean Connect the MCP servers attached to the agent automatically. When unset it is off, unless the agent has a personal integration grant, in which case it is on.
    web_search object {enabled, provider: duckduckgo or tavily or brave, api_key}
    playwright object {enabled, headless} browser automation tool
    deep_research object {enabled, max_iterations (1-50), max_depth (1-10), search_provider, tavily_api_key}

    Memory¶

    Key Type Meaning
    memory object {mode, window_messages} with mode one of none, buffer, agentscope_db, in_memory, sqlalchemy, redis
    memory_window integer 0 to 50 Number of previous messages replayed
    long_term_memory object {enabled, mode: static_control or agent_control or both, provider: qdrant}; facts survive across sessions

    Advanced¶

    Key Type Meaning
    model_routing object Per-reply routing: a router_model picks one of candidates (name, model, description) by the latest user message. Needs at least one candidate when enabled.
    structured_output boolean Ask the agent to return structured output
    allowed_agent_ids, default_participant_agent_ids list of UUID strings Used by multi-agent dialog orchestration
    hooks_enabled list of strings Lifecycle hooks to enable
    voice, elevenlabs_voice_id string Voice settings for realtime conversations
    external object Free-form metadata for provisioning systems

    Talk to an agent¶

    One request, one answer¶

    curl -s -X POST "$ARCHY_API_URL/api/v1/agents/$AGENT_ID/query" \
  -H "Authorization: Bearer $ARCHY_TOKEN" -H "Content-Type: application/json" \
  -d '{"message": "What are your support hours?"}'

    {
  "agent_id": "26fc2a0e-afe5-4c01-849b-eac03777464e",
  "session_id": "4e7c87f4-30d4-565f-a47b-9b4fca7f385a",
  "output": "Support hours are 08:00 to 18:00 CET, Monday to Friday.",
  "meta": {}
}

    A session stores the conversation. Omit session_id to start a new one. Pass it back to continue:

    curl -s -X POST "$ARCHY_API_URL/api/v1/agents/$AGENT_ID/query" \
  -H "Authorization: Bearer $ARCHY_TOKEN" -H "Content-Type: application/json" \
  -d "{\"message\": \"And on weekends?\", \"session_id\": \"$SESSION_ID\"}"

    An unknown session_id returns 404.

    No model resolved

    If no model can be resolved for the agent (no attachment, no pinned credential and no platform default), the API may answer in echo mode instead of failing: output is Echo: <your message> and meta.mode is echo (or rag+echo when the agent has a knowledge base) with a fallback_reason such as missing_agent_model_config. When a credential cannot be used, meta.mode is credential_error and meta.credential_error explains why. In every case connect and attach a model. In automated tests assert that meta.mode is none of echo, rag+echo and credential_error.

    Stream the answer¶

    For chat interfaces use Server-Sent Events. Events are start, repeated delta, then end (or error). See Running and streaming for parsers.

    curl -N -X POST "$BASE/agents/$AGENT_ID/chat/stream" \
  -H "Authorization: Bearer $ARCHY_TOKEN" -H "Content-Type: application/json" \
  -d '{"message": "Summarize our refund policy"}'

    Give the agent more abilities¶

    • Knowledge: set knowledge_base_id (see Knowledge bases).
    • Tools from MCP servers: register a server and attach it to the agent (see External MCP servers and skills).
    • Skills: attach a skill with POST .../agents/{agent_id}/skills.
    • Another model: attach one with model attachments.
    • Personal Atlassian access: grant a connection to the agent with the integration-grants endpoints.

    State, memory and plans¶

    Capability Endpoints
    Session state GET and PUT /api/v1/agents/{agent_id}/state
    Cross-session memory summaries GET .../agents/{agent_id}/memory
    Multi-step plans POST and GET /api/v1/agents/{agent_id}/plans, PUT and DELETE .../plans/{plan_id}
    Avatar PUT and GET .../agents/{agent_id}/avatar
    Audit of an agent GET /api/v1/agents/orgs/{org_id}/projects/{project_id}/agents/{agent_id}/audit

    Write a good system prompt¶

    • State the role and the audience in the first sentence.
    • Say what the agent must do when it lacks information ("ask a clarifying question", "say you do not know").
    • Name the sources it may use. For a knowledge base agent: "Answer only from the knowledge base."
    • Describe the format of the answer (length, language, bullet list, JSON).
    • Put business rules in the prompt, not in your code. Archy is domain neutral; your prompt is where your product's behavior lives.

    Python: create and chat¶

    import httpx


def create_agent(client: httpx.Client, scope: str, name: str, prompt: str, kb_id: str | None = None) -> str:
    config = {"sys_prompt": prompt, "memory": {"mode": "buffer", "window_messages": 20}}
    if kb_id:
        config["knowledge_base_id"] = kb_id
    r = client.post(f"{scope}/agents", json={"name": name, "config": config})
    r.raise_for_status()
    return r.json()["id"]


def chat(client: httpx.Client, agent_id: str) -> None:
    session_id = None
    while (message := input("you> ")) not in ("", "quit"):
        body = {"message": message, **({"session_id": session_id} if session_id else {})}
        r = client.post(f"/api/v1/agents/{agent_id}/query", json=body, timeout=120)
        r.raise_for_status()
        reply = r.json()
        session_id = reply["session_id"]
        print("agent>", reply["output"])
