    Provisioning tenants and users¶

    If you embed Archy in your own product, your backend creates the tenants. Provisioning endpoints let a service token create organizations, projects and users with ids that you choose, so your customer records and Archy tenants map one to one.

    You need

    A service token with the scopes you use (see Authentication). All provisioning calls are idempotent upserts: calling them again with the same ids is safe, which makes them easy to retry from an outbox or a job queue.

    flowchart LR
    CUST[Your customer record] -->|deterministic UUID| ORG[Organization]
    CUST -->|per workspace| PRJ[Project]
    CUST -->|per user| USR[User and membership]
    ORG --> PRJ
    PRJ --> USR

    Choose your ids¶

    Archy accepts any UUID. Derive them deterministically from your own ids so that you never have to store a mapping and a retry is always the same call:

    import uuid

ARCHY_NAMESPACE = uuid.UUID("6f1c2f66-8f5b-4c60-9a32-0d8f0a1a2b3c")  # pick one and keep it forever


def archy_id(kind: str, your_id: str) -> str:
    return str(uuid.uuid5(ARCHY_NAMESPACE, f"{kind}:{your_id}"))


org_id = archy_id("org", "customer-1042")
project_id = archy_id("project", "customer-1042/default")
user_id = archy_id("user", "user-77")

    Create an organization¶

    PUT /api/v1/integrations/provisioning/orgs/{org_id} · scope provision:org

    curl -s -X PUT "$ARCHY_API_URL/api/v1/integrations/provisioning/orgs/$ORG_ID" \
  -H "Authorization: Bearer $SERVICE_TOKEN" -H "Content-Type: application/json" \
  -d '{"name": "Globex", "settings": {"plan": "team"}}'

    {"org_id": "084d6557-5155-4851-88e3-192bea708c64", "created": true}

    settings is a free-form object stored on the organization. Calling again updates name, replaces settings as a whole (omitting it clears it) and returns created: false.

    Settings also hold platform keys

    Archy stores the organization's embedding default, platform default model and the allow_platform_llm_fallback flag in the same settings object. A later upsert that does not send them removes them. Keep your own keys in settings and read the current value (or re-apply those defaults) before you re-provision an organization that already has LLM settings.

    Create a project¶

    PUT /api/v1/integrations/provisioning/orgs/{org_id}/projects/{project_id} · scope provision:project

    curl -s -X PUT "$ARCHY_API_URL/api/v1/integrations/provisioning/orgs/$ORG_ID/projects/$PROJECT_ID" \
  -H "Authorization: Bearer $SERVICE_TOKEN" -H "Content-Type: application/json" \
  -d '{"name": "Helpdesk", "description": "Support workspace"}'
    Status Meaning
    200 Created or updated
    404 The organization does not exist. Create it first.
    409 with project_org_conflict The project id already exists under another organization. Archy never moves a project between organizations.

    Create a user¶

    PUT /api/v1/integrations/provisioning/users/{user_id} · scope provision:user

    curl -s -X PUT "$ARCHY_API_URL/api/v1/integrations/provisioning/users/$USER_ID" \
  -H "Authorization: Bearer $SERVICE_TOKEN" -H "Content-Type: application/json" \
  -d "{\"email\": \"ada@globex.example\", \"org_id\": \"$ORG_ID\", \"project_id\": \"$PROJECT_ID\"}"

    {
  "user_id": "3a2f6241-68c1-441a-bc51-fafa36ac9fda",
  "org_id": "084d6557-5155-4851-88e3-192bea708c64",
  "project_id": "5348cb7c-a373-498c-9daf-bf74e24abbb8",
  "created": true
}

    What this call does:

    • Creates the user if the id is new, with a random unusable password. Your system, or the invite flow, is the source of truth for how this user signs in.
    • Adds a membership with the admin role on the project. A user can be provisioned into many projects and organizations by calling again.
    • For an existing user it only adds the membership. It never changes the email, the password, is_active or the user's active tenant.

    Conflicts return 409 with a machine readable detail.code:

    Code Cause
    email_in_use Another user already owns this email
    email_mismatch The user id exists with a different email; emails never change
    concurrent_update Two writers raced; retry

    If the user_id already belongs to another user, the call fails with email_mismatch (or email_in_use).

    Bootstrap an organization admin¶

    POST /api/v1/integrations/provisioning/orgs/{org_id}/admins/invite · scope provision:user

    Creates (or finds) a human admin by email, grants access to projects, and returns a single-use set-password link you can send in your own onboarding email.

    curl -s -X POST "$ARCHY_API_URL/api/v1/integrations/provisioning/orgs/$ORG_ID/admins/invite" \
  -H "Authorization: Bearer $SERVICE_TOKEN" -H "Content-Type: application/json" \
  -d '{"email": "boss@globex.example"}'

    {
  "user_id": "71130610-41da-45f8-a058-9c4ba739a71d",
  "org_id": "084d6557-5155-4851-88e3-192bea708c64",
  "project_ids": ["5348cb7c-a373-498c-9daf-bf74e24abbb8"],
  "created_user": true,
  "existing_user": false,
  "existing_org_ids": [],
  "invite_link": "https://app.example.com/reset-password?token=Fg3UMgFDs8J-25ic0K3gBsEK_9H_sw83XSpfgfqx10Y",
  "expires_at": "2026-11-17T10:09:04.679975Z"
}
    Request field Meaning
    email Required. Matched case-insensitively.
    user_id Optional id to use when the user is created. If it already belongs to another user the call fails with 409 user_id_in_use.
    project_ids Projects to grant. Omit to grant all current projects of the organization.
    role admin (default) or permission-admin. A re-invite changes a role only when you pass one.
    is_active Applied only when the user is created.

    Notes:

    • The organization must already have at least one project (400 otherwise).
    • For an existing user (same email) no link is issued: invite_link and expires_at are null, existing_user is true, and only memberships are added. existing_org_ids is internal information; do not show it to tenant users.
    • The link base is the deployment setting PASSWORD_RESET_URL_BASE. The link carries a token query parameter. Your onboarding page posts it to POST /api/v1/auth/reset-password with the new password, and the user can then log in.

    To finish the bootstrap without a browser (scripts, tests, CI):

    TOKEN=$(echo "$INVITE" | jq -r '.invite_link' | sed 's/.*token=//')
curl -s -X POST "$ARCHY_API_URL/api/v1/auth/reset-password" \
  -H "Content-Type: application/json" \
  -d "{\"token\": \"$TOKEN\", \"new_password\": \"a-long-unique-passphrase\"}"

    Look up a user by email¶

    GET /api/v1/integrations/provisioning/users/by-email/{email} · scope provision:user:read

    curl -s "$ARCHY_API_URL/api/v1/integrations/provisioning/users/by-email/ada@globex.example" \
  -H "Authorization: Bearer $SERVICE_TOKEN"

    Returns the user id and active tenant, or 404. Several accounts that differ only by case give 409 email_ambiguous.

    Push LLM credentials (optional)¶

    If your product stores the customer's provider keys, you can push them instead of asking the customer to call the LLM endpoints. Scope provision:credential.

    PUT /api/v1/integrations/provisioning/orgs/{org_id}/llm-credentials

    curl -s -X PUT "$ARCHY_API_URL/api/v1/integrations/provisioning/orgs/$ORG_ID/llm-credentials" \
  -H "Authorization: Bearer $SERVICE_TOKEN" -H "Content-Type: application/json" \
  -d '{
    "credentials": [{
      "credential_id": "5e1f3c52-2f67-4b5e-9d51-0c2f7f3e8a10",
      "provider": "openai",
      "display_name": "Customer OpenAI",
      "api_key": "<provider key>",
      "is_default": true
    }]
  }'

    {"org_id": "...", "upserted": 1, "created": 1, "updated": 0}
    • Items are upserted by credential_id, which you supply, so retries are safe.
    • A credential can be scoped to a project with project_id.
    • DELETE .../llm-credentials/{credential_id} is idempotent: deleting an absent credential returns deleted: false, not 404. A credential owned by another organization is never deleted (409).
    • Every push sets is_verified, verified_at and is_default to the values you send (all default to false). Send is_verified: true on every push if you verified the key yourself; a later push without it un-verifies a credential, and unverified credentials are skipped at runtime. To verify through Archy instead, an admin user calls POST /llm-providers/credentials/{id}/verify.
    • project_id is fixed when a credential is first created; later pushes do not move it.

    Signed requests¶

    A deployment can require signed requests on this channel (PROVISIONING_SIGNATURE_REQUIRED). The signature is an HMAC-SHA256 over a canonical string, sent in three headers:

    import hashlib
import hmac
import secrets
import time


def signed_headers(secret: str, method: str, path: str, body: bytes) -> dict[str, str]:
    timestamp = str(int(time.time()))
    nonce = secrets.token_urlsafe(24)
    signing_string = "\n".join([method.upper(), path, timestamp, nonce, hashlib.sha256(body).hexdigest()])
    signature = hmac.new(secret.encode(), signing_string.encode(), hashlib.sha256).hexdigest()
    return {"X-Archy-Timestamp": timestamp, "X-Archy-Nonce": nonce, "X-Archy-Signature": signature}

    path is the request path without query string. The timestamp must be within the configured window (300 seconds by default) and every nonce is accepted once. A failed check returns 401 Invalid request signature.

    How your users sign in¶

    The provisioned user exists; now they need a token. Pick one:

    Approach How Choose when
    Set-password link Send the invite_link; the user sets a password and logs in with POST /auth/login You want Archy to own the credentials
    Your identity provider The operator enables external auth; your IdP issues tokens with org_id and project_id claims You already run SSO
    Your backend as proxy Your backend holds a user token (for example from a service account user) and calls Archy for your users The end user never talks to Archy directly

    A provisioning client in Python¶

    import os
import httpx


class Provisioner:
    def __init__(self, base_url: str, service_token: str) -> None:
        self.http = httpx.Client(
            base_url=base_url, headers={"Authorization": f"Bearer {service_token}"}, timeout=30
        )

    def _send(self, method: str, url: str, **kwargs) -> dict:
        response = self.http.request(method, url, **kwargs)
        if response.status_code == 409:
            raise RuntimeError(response.json()["detail"])  # {"code": ..., "message": ...}
        response.raise_for_status()
        return response.json()

    def ensure_org(self, org_id: str, name: str) -> dict:
        return self._send("PUT", f"/api/v1/integrations/provisioning/orgs/{org_id}", json={"name": name})

    def ensure_project(self, org_id: str, project_id: str, name: str) -> dict:
        return self._send(
            "PUT",
            f"/api/v1/integrations/provisioning/orgs/{org_id}/projects/{project_id}",
            json={"name": name},
        )

    def invite_admin(self, org_id: str, email: str) -> dict:
        return self._send(
            "POST", f"/api/v1/integrations/provisioning/orgs/{org_id}/admins/invite", json={"email": email}
        )


p = Provisioner(os.environ["ARCHY_API_URL"], os.environ["SERVICE_TOKEN"])
# archy_id is the helper from "Choose your ids"
org, project = archy_id("org", "customer-1042"), archy_id("project", "customer-1042/default")
p.ensure_org(org, "Globex")
p.ensure_project(org, project, "Helpdesk")
print(p.invite_admin(org, "boss@globex.example")["invite_link"])

    Error reference¶

    Status Typical cause
    400 Inviting an admin into an organization without projects
    401 Invalid token or invalid request signature
    403 Missing scopes: ... Mint the token with the named scope
    403 Service token required A user token was used on a provisioning route
    403 Forbidden enforce binding mode and the token lacks tenant:act or does not list the organization in org_ids (PUT .../users/{id} checks the organization in the request body)
    404 Organization or project not found
    409 See the codes above
