    Authentication and tokens¶

    Every API call needs a bearer token, except the health probes, the /auth/* endpoints (register, login, forgot and reset password) and the OAuth endpoints:

    Authorization: Bearer <token>

    A missing or malformed header returns 401 with {"detail": "Missing bearer token"}.

    Token types at a glance¶

    Token Identifies Lifetime Where it is accepted
    User token (JWT) A user acting in one org and project Login: 8 hours, or 7 days with remember_me. Register and tenant switch: 30 minutes. All tenant routes
    Service token (JWT) A backend system and its scopes Chosen by the issuer Provisioning routes, and tenant routes for the organization and project in the request
    MCP API key (archy_mcp_...) A project and a scope (mcp:tools; mcp:read when granted through OAuth) 1 to 365 days, or never MCP server and the MCP routes of the API
    External IdP token (JWT) The user named in the claims Set by your IdP All tenant routes, when the operator enabled it

    User tokens¶

    Register¶

    Creates a user together with a new organization and project, and returns a token.

    curl -s -X POST "$ARCHY_API_URL/api/v1/auth/register" \
  -H "Content-Type: application/json" \
  -d '{"email": "dev@example.com", "password": "a-long-unique-passphrase", "org_name": "Acme", "project_name": "Support"}'

    {
  "access_token": "eyJhbGciOiJIUzI1NiIs...",
  "token_type": "bearer",
  "user_id": "0888cd4e-1746-4009-ad52-53f369120227",
  "org_id": "84eab6dd-2cc1-41d9-a5e7-0c5e38197865",
  "project_id": "f834cf48-7bf7-4489-8b4b-9c7d8c832cb5",
  "available_orgs": [{"org_id": "84eab6dd-2cc1-41d9-a5e7-0c5e38197865", "name": "Acme", "project_count": 1}]
}
    • email must be unique; a duplicate returns 409.
    • password is 8 to 128 characters (a shorter one fails request validation with 422).
    • The returned token lasts 30 minutes. Use POST /auth/login (8 hours, or 7 days with remember_me) for longer sessions.
    • A self-registered user has the permission-admin role. See Roles.

    Log in¶

    curl -s -X POST "$ARCHY_API_URL/api/v1/auth/login" \
  -H "Content-Type: application/json" \
  -d '{"email": "dev@example.com", "password": "a-long-unique-passphrase", "remember_me": false}'

    The response has the same shape as register. Wrong credentials return 401 Invalid credentials for every cause (unknown email, wrong password, inactive account), so the response does not reveal which accounts exist.

    Inspect and switch tenant¶

    A user can belong to several organizations and projects. The token is bound to one pair; switch to get a new token for another pair.

    # Who am I, and in which tenant?
curl -s "$ARCHY_API_URL/api/v1/tenancy/whoami" -H "Authorization: Bearer $ARCHY_TOKEN"

# Organizations and projects I belong to
curl -s "$ARCHY_API_URL/api/v1/tenancy/orgs" -H "Authorization: Bearer $ARCHY_TOKEN"
curl -s "$ARCHY_API_URL/api/v1/tenancy/projects?org_id=$ORG_ID" -H "Authorization: Bearer $ARCHY_TOKEN"

# Switch; the response contains a new access_token
curl -s -X POST "$ARCHY_API_URL/api/v1/tenancy/switch" \
  -H "Authorization: Bearer $ARCHY_TOKEN" -H "Content-Type: application/json" \
  -d "{\"org_id\": \"$ORG_ID\", \"project_id\": \"$PROJECT_ID\"}"

    Switching to a project you are not a member of returns 403 Not a member of this project. The new token lasts 30 minutes, and the switched organization and project become your default for the next login.

    Reset a password¶

    curl -s -X POST "$ARCHY_API_URL/api/v1/auth/forgot-password" \
  -H "Content-Type: application/json" -d '{"email": "dev@example.com"}'

curl -s -X POST "$ARCHY_API_URL/api/v1/auth/reset-password" \
  -H "Content-Type: application/json" -d '{"token": "<token from the email link>", "new_password": "a-new-long-unique-passphrase"}'

    forgot-password always returns 200, whether or not the email exists. Reset tokens are single use and expire. A successful reset invalidates every token issued earlier for that user.

    Python helper¶

    import os
import httpx


class ArchyClient:
    """Logs in, injects the bearer token and logs in again once on a 401."""

    def __init__(self, base_url: str, email: str, password: str) -> None:
        self.http = httpx.Client(base_url=base_url, timeout=60)
        self.email, self.password = email, password
        self.login()

    def login(self) -> None:
        r = self.http.post("/api/v1/auth/login", json={"email": self.email, "password": self.password})
        r.raise_for_status()
        body = r.json()
        self.org_id, self.project_id = body["org_id"], body["project_id"]
        self.http.headers["Authorization"] = f"Bearer {body['access_token']}"

    def request(self, method: str, url: str, **kwargs) -> httpx.Response:
        response = self.http.request(method, url, **kwargs)
        if response.status_code == 401:
            self.login()
            response = self.http.request(method, url, **kwargs)
        response.raise_for_status()
        return response


client = ArchyClient(os.environ["ARCHY_API_URL"], os.environ["ARCHY_EMAIL"], os.environ["ARCHY_PASSWORD"])
print(client.request("GET", "/api/v1/tenancy/whoami").json())

    Rate limits¶

    Register and login are throttled per client IP and per account; reset-password per client IP and per reset token. When the budget is used up the API returns 429 with a Retry-After header (the length of the throttle window in seconds, 60 by default). Back off for at least that long. forgot-password is throttled silently: it keeps returning 200.

    Service tokens¶

    A service token authenticates a system, not a person. It normally carries scopes and no tenant. You use it to provision organizations, projects and users.

    Claims of a service token:

    Claim Meaning
    sub Name of the calling system
    token_type service
    scope Space separated scopes
    org_ids Optional list of organization ids the token may act for
    exp Expiry

    Scopes:

    Scope Allows
    provision:org PUT /integrations/provisioning/orgs/{org_id}
    provision:project PUT .../orgs/{org_id}/projects/{project_id}
    provision:user PUT .../users/{user_id} and POST .../orgs/{org_id}/admins/invite
    provision:user:read GET .../users/by-email/{email}
    provision:credential Push and delete LLM credentials for an organization
    tenant:act Needed together with org_ids when the deployment runs in enforce binding mode

    Tenant binding

    A deployment can run service tokens in audit mode (default: every use is logged with the organization it targeted) or enforce mode (on routes that target an organization the token must have tenant:act and list the organization in org_ids, otherwise 403 Forbidden). The user lookup by email is only audited. Ask the operator which mode applies and request a token bound to the organizations you manage.

    Service tokens are issued by the operator of the deployment. For local development you can mint one yourself, see Run Archy locally.

    Using a service token on a route that needs a user returns 403 User token required; using a user token on a provisioning route returns 403 Service token required.

    Acting on tenant routes¶

    A service token with at least one scope can also call the tenant routes (agents, knowledge bases, workflows, runs, ...) for the organization and project named in the path. This is how a backend operates a customer's workspace without holding a user session. Rules to know:

    • The tenant comes from the request: the org_id and project_id in the path (/orgs/{org_id}/projects/{project_id}/...) or, on routes that take them as optional query parameters (for example /agents/{agent_id}/query), from ?org_id=...&project_id=.... Organization-scoped routes need only org_id. Without a tenant the API returns 401 Missing org_id, which is why GET /tenancy/whoami returns 401 for a service token.
    • It has no organization admin rights. Operations that need an admin user, such as POST /llm-providers/credentials?org_id=...&project_id=... or PUT /llm-providers/model-attachments/org?org_id=..., return 403 Org admin role required. Push credentials with the provisioning endpoint and pin a model in the agent config instead (see Onboard customers from your backend).
    • In enforce binding mode the token must carry the tenant:act scope and list the organization in org_ids, otherwise the API returns 403 Forbidden.
    • A run started this way has no initiating user, so personal connections are unavailable to it.

    MCP API keys¶

    An API key lets an IDE or agent client use the MCP server without an interactive login.

    # Create (a user token, or a service token for that organization and project). The raw token is shown once.
curl -s -X POST "$ARCHY_API_URL/api/v1/orgs/$ORG_ID/projects/$PROJECT_ID/mcp-tokens" \
  -H "Authorization: Bearer $ARCHY_TOKEN" -H "Content-Type: application/json" \
  -d '{"name": "my-ide", "expires_in_days": 90}'

# List, revoke (stops working, row kept) or delete with DELETE .../mcp-tokens/$TOKEN_ID
curl -s "$ARCHY_API_URL/api/v1/orgs/$ORG_ID/projects/$PROJECT_ID/mcp-tokens" -H "Authorization: Bearer $ARCHY_TOKEN"
curl -s -X POST "$ARCHY_API_URL/api/v1/orgs/$ORG_ID/projects/$PROJECT_ID/mcp-tokens/$TOKEN_ID/revoke" -H "Authorization: Bearer $ARCHY_TOKEN"

    {
  "id": "0dd516ed-3c38-47a7-bfd1-3dd7cec3be3f",
  "name": "my-ide",
  "token_prefix": "archy_mcp_0a1b2c3d",
  "token": "archy_mcp_0a1b2c3d<random characters, shown once>",
  "expires_at": "2027-02-15T09:09:03.996701",
  "created_at": "2026-11-17T09:09:03.997580"
}

    expires_in_days is 1 to 365 and defaults to 90 when omitted; send null explicitly for a key that never expires. The response (201) also contains org_id, project_id and description. Store the token value in a secret manager immediately. It cannot be read again. See Connect a client for scopes and usage.

    External identity provider tokens¶

    If you operate your own deployment you can let Archy trust tokens from your IdP (Microsoft Entra, Auth0, Keycloak or any OIDC provider that publishes a JWKS):

    EXTERNAL_AUTH_ENABLED=true
EXTERNAL_AUTH_ISSUER=https://login.example.com/
EXTERNAL_AUTH_AUDIENCE=archy-api
EXTERNAL_AUTH_JWKS_URL=https://login.example.com/.well-known/jwks.json
EXTERNAL_AUTH_ALGORITHMS=RS256

    The token must carry iss, aud and a subject (sub, or oid, appid, azp or client_id). A user token must also carry org_id and project_id claims, otherwise it is rejected. Application-only tokens (token_type=service, grant_type=client_credentials, idtyp=app, or roles without scp or scope) are treated as service tokens. Scopes come from the scope claim; if it is absent, from scp; if that is absent, from roles. The role org-admin grants organization admin rights. The deployment refuses external tokens when issuer and audience are not configured.

    Revocation and security notes¶

    • Password reset revokes tokens. Tokens issued by Archy carry a version. Resetting the password increments it, so older tokens return 401 Token revoked.
    • Deactivated users stop working. A deactivated user's Archy tokens and MCP keys are rejected. External IdP tokens and service tokens are not revoked this way: they stay valid until they expire, so revoke them at the source.
    • Tenant mismatch is 403. If the org_id or project_id in the path differ from the token, the API returns 403 Forbidden without saying whether the resource exists.
    • Keep tokens out of logs and URLs. Send them only in the Authorization header and never log them in your own code.
    • Use the narrowest token. Keys created with the API carry the write-capable mcp:tools scope; for read-only clients let the client request mcp:read through OAuth. Bind service tokens to organizations in enforce mode.
