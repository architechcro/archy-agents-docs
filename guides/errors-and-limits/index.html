    Errors, limits and practices¶

    Error format¶

    Errors are JSON. Error bodies include a request_id that you should log and quote when you contact support. The same id is returned in the X-Request-ID response header. You can send your own X-Request-ID header to correlate a request across systems.

    {"detail": "Missing bearer token", "request_id": "7368bf69-6315-4840-aa0c-db87925e42f9"}

    A malformed body names each problem. loc is the path to the field.

    {
  "detail": [
    {"type": "missing", "loc": ["body", "name"], "msg": "Field required", "input": {}}
  ]
}

    Some endpoints return a stable machine readable code. Branch on code, not on message.

    {"detail": {"code": "email_in_use", "message": "Email is already used by a different user"}}

    An invalid agent config:

    {"detail": {"message": "Invalid config", "errors": [{"type": "extra_forbidden", "loc": ["bogus"], "msg": "Extra inputs are not permitted"}]}}

    Streaming endpoints cannot change the HTTP status after the first byte. Failures arrive inside the stream: an SSE error event or an NDJSON object with "event": "error". Always handle them.

    Status codes¶

    Status Meaning What to do
    200, 201 Success. Creates return 201 for most resources.
    202 Accepted for background work (POST .../runs) Poll the run
    400 Invalid request that is not a schema error, for example an invalid agent config Fix the payload
    401 Missing, invalid, expired or revoked token Log in again; do not retry blindly
    403 The token is valid but not allowed: wrong tenant, missing role or scope Check the org and project ids, the role and the service token scopes
    404 The resource does not exist in your tenant Check the id. A resource of another tenant also returns 404 or 403, never its content
    409 Conflict, such as a duplicate email or a concurrent update Read detail.code; retry on concurrent_update
    422 The body failed validation, or a workflow input is invalid Fix the payload; for workflows read detail.code and errors
    429 Rate limited Wait for Retry-After seconds
    5xx Server or dependency failure Retry with backoff; if it persists send the request_id to support

    Model and credential problems¶

    These are not authentication errors:

    Symptom Cause Fix
    credential_error in an agent result No verified LLM credential and the platform fallback is off Add and verify a credential, attach a model
    422 Credential must be verified before attaching a model Attachment to an unverified credential Run POST .../credentials/{id}/verify
    403 Org admin role required Creating credentials needs an admin membership Use an admin, see Roles
    Run fails with MCP_UNAVAILABLE A required MCP server is not connected Check server health
    Indexing stays failed The embedding model call failed Read the job's error_message; check the embedding default credential

    Rate limits¶

    • POST /auth/login, /auth/register and /auth/reset-password are limited per client IP and per account. A limited call returns 429 with Retry-After.
    • POST /llm-providers/test is limited per user.
    • Model providers apply their own limits. Archy retries rate-limited model calls with exponential backoff before failing a run.
    • Deployments can also enforce limits at their gateway. Treat every 429 as retryable after the indicated delay.

    Retrying safely¶

    Operation Safe to retry? Notes
    GET Yes
    Provisioning PUT and the credential DELETE Yes Idempotent by design
    POST .../index Yes Each document has at most one job
    POST that creates (agents, workflows, knowledge bases) No A retry after a timeout can create a duplicate. List first, or use unique names.
    POST .../query, .../execute Careful A retry runs the model again and consumes tokens. Pass the same session_id to continue rather than restart.

    Use exponential backoff with jitter, for example 1 s, 2 s, 4 s, 8 s plus a random 0 to 25 percent, and give up after a few attempts.

    import random
import time

import httpx


def request_with_retry(client: httpx.Client, method: str, url: str, *, attempts: int = 5, **kwargs) -> httpx.Response:
    for attempt in range(attempts):
        try:
            response = client.request(method, url, **kwargs)
        except (httpx.ConnectError, httpx.ReadTimeout):
            response = None
        if response is not None and response.status_code not in (429, 502, 503, 504):
            return response
        delay = float(response.headers.get("Retry-After", 0)) if response is not None else 0
        time.sleep(max(delay, 2**attempt) * (1 + random.random() * 0.25))
    raise RuntimeError(f"{method} {url} failed after {attempts} attempts")

    Pagination and filtering¶

    List endpoints that can grow take limit and offset query parameters (for example sessions, artifacts, handoff requests). Page until a response returns fewer items than limit. Filters are explicit query parameters, listed on each reference page.

    Security checklist¶

    • Keep service tokens on servers only. Never ship them to browsers or mobile apps.
    • Give each integration its own service token with only the scopes it needs, and rotate it.
    • Do not log Authorization headers, provider keys or invite_link values.
    • Send provider keys only when creating or rotating a credential, over TLS.
    • Treat model output as untrusted input: validate structured output with structured_output_schema before acting on it.
    • Prefer organization-scoped credentials owned by customers (bring your own key) over sharing one key across tenants.

    Performance practices¶

    • Stream for interactive UIs; use async runs for long jobs.
    • Reuse session_id for follow-up questions instead of resending history.
    • Keep knowledge bases focused and top_k small.
    • Use the cheapest model that meets quality for classification and routing steps, and a stronger one only where needed (see model attachments).
    • Set max_tokens, max_iters and token_budget on agents that call tools, so a bad prompt cannot run away.
    • Read usage regularly (token usage) and alert on spikes.
