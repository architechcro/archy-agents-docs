    Running and streaming¶

    Archy offers three ways to execute an agent or workflow. Pick by what your caller can do.

    Mode Use when Agent Workflow
    Synchronous Short tasks; you can wait for the final result POST /agents/{id}/query POST .../workflows/{id}/execute
    Streaming A UI should show progress as it happens POST .../agents/{id}/chat/stream (SSE) POST .../workflows/{id}/execute/stream (SSE)
    Asynchronous Your caller cannot hold a connection open (serverless, Atlassian Forge, queues) POST .../workflows/{id}/runs, then GET .../runs/{run_id}

    All requests need a bearer token (Authentication).

    Server-Sent Events (SSE)¶

    Streaming endpoints respond with Content-Type: text/event-stream. Each event is two lines and a blank line:

    event: delta
data: {"delta": "Support hours are "}

    Use fetch, not EventSource

    Browsers' EventSource cannot send an Authorization header or a POST body. Read the stream with fetch and a ReadableStream, or let your backend relay it.

    Agent chat stream¶

    POST /api/v1/orgs/{org_id}/projects/{project_id}/agents/{agent_id}/chat/stream with {"message": "...", "session_id": "..."}.

    Event data
    start {"agent_id", "session_id"}
    delta {"delta": "<text chunk>"}, repeated
    end {"agent_id", "session_id", "output", "meta"}
    error {"error": "execution_failed", "detail": "..."}

    The error event replaces end. Handle it: the HTTP status is already 200 when it is sent.

    delta events are chunks of a finished answer

    The agent runs to completion first; delta events then deliver the final output in chunks of about 20 characters. There is no token-level streaming, so the first delta arrives only after the agent has finished. Use the stream to render text progressively, and show your own progress indicator until the first delta arrives. POST /api/v1/agents/{agent_id}/query/stream is a test stub that echoes the message; do not use it.

    curl -N -X POST "$ARCHY_API_URL/api/v1/orgs/$ORG_ID/projects/$PROJECT_ID/agents/$AGENT_ID/chat/stream" \
  -H "Authorization: Bearer $ARCHY_TOKEN" -H "Content-Type: application/json" \
  -d '{"message": "Summarize our refund policy"}'

    import json
import os

import httpx


def sse_events(response: httpx.Response):
    """Yield (event, data) pairs from an SSE response."""
    event, data_lines = "message", []
    for line in response.iter_lines():
        if line == "":
            if data_lines:
                yield event, json.loads("\n".join(data_lines))
            event, data_lines = "message", []
        elif line.startswith("event:"):
            event = line[6:].strip()
        elif line.startswith("data:"):
            data_lines.append(line[5:].lstrip())


base = os.environ["ARCHY_API_URL"]
headers = {"Authorization": f"Bearer {os.environ['ARCHY_TOKEN']}"}
url = f"{base}/api/v1/orgs/{os.environ['ORG_ID']}/projects/{os.environ['PROJECT_ID']}/agents/{os.environ['AGENT_ID']}/chat/stream"

with httpx.stream("POST", url, headers=headers, json={"message": "Hello"}, timeout=None) as response:
    response.raise_for_status()
    for event, data in sse_events(response):
        if event == "delta":
            print(data["delta"], end="", flush=True)
        elif event == "error":
            raise RuntimeError(data["detail"])

    export async function* sse(response: Response): AsyncGenerator<{ event: string; data: any }> {
  const reader = response.body!.pipeThrough(new TextDecoderStream()).getReader();
  let buffer = "";
  for (;;) {
    const { value, done } = await reader.read();
    if (done) return;
    buffer += value;
    let boundary: number;
    while ((boundary = buffer.indexOf("\n\n")) >= 0) {
      const block = buffer.slice(0, boundary);
      buffer = buffer.slice(boundary + 2);
      let event = "message";
      const data: string[] = [];
      for (const line of block.split("\n")) {
        if (line.startsWith("event:")) event = line.slice(6).trim();
        else if (line.startsWith("data:")) data.push(line.slice(5).trimStart());
      }
      if (data.length) yield { event, data: JSON.parse(data.join("\n")) };
    }
  }
}

const response = await fetch(`${base}/api/v1/orgs/${org}/projects/${project}/agents/${agent}/chat/stream`, {
  method: "POST",
  headers: { Authorization: `Bearer ${token}`, "Content-Type": "application/json" },
  body: JSON.stringify({ message: "Hello" }),
});
for await (const { event, data } of sse(response)) {
  if (event === "delta") process.stdout.write(data.delta);
}

    NDJSON: knowledge base retrieval preview¶

    POST .../agents/{agent_id}/query with {"kb_id": "...", "query": "...", "top_k": 3, "min_score": 0.2} returns application/x-ndjson: one JSON object per line with an event field: agent_start, retrieval (the retrieved chunks), agent_final (its response joins the chunks) or error (with a message). It is a retrieval preview: no model is called.

    with httpx.stream("POST", url, headers=headers, json={"kb_id": kb_id, "query": "Refund window?"}, timeout=None) as r:
    for line in r.iter_lines():
        if line:
            event = json.loads(line)
            print(event)

    Workflow execution¶

    Synchronous¶

    POST .../workflows/{id}/execute returns when the run finishes. See Workflows for the response. Use a generous client timeout: runs can take minutes.

    Streaming¶

    POST .../workflows/{id}/execute/stream accepts the same body as execute.

    Event Meaning
    start {"workflow_id", "workflow_type", "session_id", "run_id"}
    step_started, step_completed Per agent (orchestrator workflows)
    token, discussion Text from agents (other types)
    run.started, node.started, node.delta, node.completed, edge.active, run.completed The unified trace envelope: {"v", "seq", "ts", "run_id", "workflow_id", ...}
    structured_output The complete, validated object, sent once when a structured_output_schema is set; run.completed carries the same object
    end {"session_id", "output", "structured_output", "audit", "error", "structured_output_error", "run_id", "status", "pending_input"}. status is awaiting_input when the run paused at a checkpoint.
    error Replaces end on failure

    Treat unknown fields and event types as forward compatible. Each trace envelope has a seq.

    A stream cannot reattach to a run in progress

    Calling the endpoint again with a session_id and ?after_seq=<last seq> first replays the persisted trace envelopes of that session with a higher seq (they are written when a run ends), and then starts a new run of the workflow with your message on that session. It does not attach to a run that is still executing, and seq restarts at 1 for each execution. For runs that must survive a disconnect, use asynchronous runs.

    url = f"{base}/api/v1/orgs/{org_id}/projects/{project_id}/workflows/{workflow_id}/execute/stream"
body = {"message": "Run the weekly report", "inputs": {"week": "2026-W46"}}
with httpx.stream("POST", url, headers=headers, json=body, timeout=None) as r:
    for event, data in sse_events(r):
        if event == "node.started":
            print("running", data.get("node_id"))
        elif event == "end":
            print(data["status"], data["output"])

    Asynchronous runs¶

    For callers that cannot stream, start a run and poll it.

    # 1. Start. Same body as /execute. Returns immediately.
curl -s -X POST "$BASE/workflows/$WORKFLOW_ID/runs" \
  -H "Authorization: Bearer $ARCHY_TOKEN" -H "Content-Type: application/json" \
  -d '{"message": "Run the weekly report", "inputs": {"week": "2026-W46"}}'
# {"run_id": "…", "status": "pending"}   (HTTP 202)

# 2. Poll
curl -s "$BASE/workflows/$WORKFLOW_ID/runs/$RUN_ID" -H "Authorization: Bearer $ARCHY_TOKEN"

    status is pending, running, awaiting_input, succeeded, failed or cancelled (a run paused at a checkpoint that was cancelled). output, structured_output, audit and error are filled once the run is succeeded or failed.

    import time


def run_and_wait(client, scope: str, workflow_id: str, message: str, *, timeout: float = 600, **inputs) -> dict:
    started = client.post(f"{scope}/workflows/{workflow_id}/runs", json={"message": message, "inputs": inputs or None})
    started.raise_for_status()
    run_id = started.json()["run_id"]

    delay, deadline = 1.0, time.monotonic() + timeout
    while time.monotonic() < deadline:
        run = client.get(f"{scope}/workflows/{workflow_id}/runs/{run_id}").json()
        if run["status"] in ("succeeded", "failed", "awaiting_input", "cancelled"):
            return run
        time.sleep(delay)
        delay = min(delay * 1.5, 10)  # back off to a 10 second poll
    raise TimeoutError(f"run {run_id} still running")

    There is no endpoint that lists asynchronous runs, so keep the run_id you receive. GET .../workflows/{id}/sessions lists sessions.

    Service-token runs

    A run started with a service token and no acting-user identity has no initiating user. Storage nodes can then only use project and organization connections that have a root folder, not personal connections.

    Pause and resume at a checkpoint¶

    When a composite workflow reaches a checkpoint node the response has status: "awaiting_input", output is the rendered prompt and pending_input describes the question: {status, question, node_id, node_name, iteration}. This holds for /execute, /resume and the stream end event. An asynchronous run reports status: "awaiting_input" with the prompt in output and the run's session_id; read the structured question from the session (GET .../workflows/{id}/sessions/{session_id}, state.pending_input).

    # Resume with the answer
curl -s -X POST "$BASE/workflows/$WORKFLOW_ID/sessions/$SESSION_ID/resume" \
  -H "Authorization: Bearer $ARCHY_TOKEN" -H "Content-Type: application/json" \
  -d '{"answer": "Approved. Add the pricing table."}'

# Or cancel; the run is marked cancelled and cannot resume
curl -s -X POST "$BASE/workflows/$WORKFLOW_ID/sessions/$SESSION_ID/cancel" -H "Authorization: Bearer $ARCHY_TOKEN"
    • answer is 1 to 32,768 characters.
    • Declared sensitive inputs are not stored with the paused run; send them again in inputs on resume. Any other key returns 422 with detail.code = WORKFLOW_INPUTS_INVALID (INPUT_UNKNOWN), and a missing required sensitive input gives INPUT_REQUIRED. The run keeps waiting.
    • Passing the session_id of a paused run to /execute also resumes it. Invalid inputs return 422 and the run stays resumable.
    • Checkpoints expire after 7 days by default. Expiry is detected when a resume is tried: that call returns 409 and marks the run failed. Until then the session still shows awaiting_input.

    The full walkthrough is in Human approval checkpoint.

    Dialog runs¶

    Multi-agent dialogs have their own resource: POST .../dialog-runs creates one, POST .../dialog-runs/{run_id}/execute streams it as NDJSON, and GET, PATCH and DELETE manage it. See the Workflows reference.

    Choosing timeouts¶

    Layer Recommendation
    Client read timeout for streams None (disabled) with your own idle watchdog
    Client timeout for sync execute 5 minutes or more
    Proxies and gateways Disable response buffering for text/event-stream and raise idle timeouts
    Polling interval 1 s growing to 10 s
