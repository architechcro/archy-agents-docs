    LLM providers and models¶

    Archy uses a bring-your-own-LLM model: every organization connects its own provider and chooses which model each agent runs on. Provider API keys are encrypted at rest and are never returned by any endpoint.

    flowchart LR
    CRED[LLM credential<br/>provider, base URL, API key] -->|verify| OK[Verified]
    OK --> ATT[Model attachment<br/>credential + model name]
    ATT --> A1[Agent]
    ATT --> A2[Project default]
    ATT --> A3[Organization default]
    OK --> EMB[Embedding default<br/>for knowledge bases]

    Supported providers¶

    GET /api/v1/llm-providers/presets returns the catalog (no secrets). A preset maps a friendly choice to a backend provider type plus defaults.

    Preset key provider to send Default base_url Notes
    azure_openai azure_openai your resource endpoint (required) Also needs api_version (default 2024-12-01-preview). The model name is the deployment name.
    openai openai https://api.openai.com/v1
    groq openai_compatible https://api.groq.com/openai/v1
    deepseek deepseek https://api.deepseek.com Chat only; no embeddings.
    gemini openai_compatible https://generativelanguage.googleapis.com/v1beta/openai
    claude openai_compatible https://api.anthropic.com/v1
    cloudflare openai_compatible none; the preset returns base_url_template https://api.cloudflare.com/client/v4/accounts/{account_id}/ai/v1 Replace {account_id} and send the result as base_url.
    ollama ollama http://localhost:11434 Local models. The operator must allow local URLs.
    custom openai_compatible none (required) Any OpenAI-compatible endpoint.

    Providers whose models can be listed (supports_model_list is true in the presets) are openai, deepseek, ollama and every openai_compatible preset. azure_openai cannot list deployments.

    Add a credential¶

    Changing LLM configuration needs an admin: creating, updating, deleting, setting a default and verifying credentials, and also model attachments, the platform default model and the embedding default. You are an admin when you have the admin role on the project in your token, the org-admin role from your identity provider, or a platform admin grant. Reads (list, get, models, presets, test) need only membership. See Roles.

    The credential belongs to the organization of your token. Set project_id to scope it to one project.

    curl -s -X POST "$ARCHY_API_URL/api/v1/llm-providers/credentials" \
  -H "Authorization: Bearer $ARCHY_TOKEN" -H "Content-Type: application/json" \
  -d '{"provider": "openai", "display_name": "OpenAI production", "api_key": "<key>"}'

    curl -s -X POST "$ARCHY_API_URL/api/v1/llm-providers/credentials" \
  -H "Authorization: Bearer $ARCHY_TOKEN" -H "Content-Type: application/json" \
  -d '{
    "provider": "azure_openai",
    "display_name": "Azure EU",
    "api_key": "<key>",
    "base_url": "https://my-resource.openai.azure.com/",
    "api_version": "2024-12-01-preview",
    "extra_config": {"test_model": "<your deployment name>"}
  }'

    curl -s -X POST "$ARCHY_API_URL/api/v1/llm-providers/credentials" \
  -H "Authorization: Bearer $ARCHY_TOKEN" -H "Content-Type: application/json" \
  -d '{
    "provider": "openai_compatible",
    "display_name": "Claude",
    "api_key": "<key>",
    "base_url": "https://api.anthropic.com/v1",
    "extra_config": {"test_model": "<a Claude model id>"}
  }'

    curl -s -X POST "$ARCHY_API_URL/api/v1/llm-providers/credentials" \
  -H "Authorization: Bearer $ARCHY_TOKEN" -H "Content-Type: application/json" \
  -d '{"provider": "ollama", "display_name": "Local Ollama", "base_url": "http://localhost:11434"}'

    Outbound URLs are validated against private and loopback ranges. For local development the operator sets SSRF_ALLOW_LOCAL_URLS=true; keep it false in shared environments.

    The response never contains the key. has_api_key tells you that one is stored:

    {
  "id": "864beb2b-32f1-4ee1-aa0c-ccdd1ba34948",
  "org_id": "35af6d8d-f874-4b2b-9222-122092075307",
  "project_id": null,
  "provider": "openai",
  "display_name": "OpenAI prod",
  "has_api_key": true,
  "base_url": null,
  "api_version": null,
  "extra_config": {},
  "is_default": false,
  "is_verified": false,
  "verified_at": null,
  "key_id": null,
  "created_at": "2026-11-17T09:09:35.717955",
  "updated_at": "2026-11-17T09:09:35.717957"
}

    Test and verify¶

    You can test a key before saving it. This makes a one token request and is rate limited per user:

    curl -s -X POST "$ARCHY_API_URL/api/v1/llm-providers/test" \
  -H "Authorization: Bearer $ARCHY_TOKEN" -H "Content-Type: application/json" \
  -d '{"provider": "openai", "api_key": "<key>", "model_name": "gpt-4o-mini"}'
# {"success": true, "latency_ms": 380, "model_used": "gpt-4o-mini", "error": null}

    After saving, verify the stored credential. Runtime only uses verified credentials.

    Verification sends a one token request to the model named in extra_config.test_model. Without it, openai and azure_openai use gpt-4o-mini, deepseek uses deepseek-chat and ollama uses llama3. openai_compatible providers (Groq, Gemini, Claude, Cloudflare, custom) have no default: verification fails with "No test model configured" until you set extra_config.test_model. For Azure, use a deployment name that exists in your resource.

    curl -s -X POST "$ARCHY_API_URL/api/v1/llm-providers/credentials/$CRED_ID/verify" \
  -H "Authorization: Bearer $ARCHY_TOKEN"

    {"success": false, "is_verified": false, "verified_at": null, "latency_ms": null, "error": "Authentication failed — check your API key"}

    Changing api_key or base_url resets verification, so verify again after a rotation.

    List the models a credential offers (providers that support listing return names; for the others supports_listing is false and you type the model name):

    curl -s "$ARCHY_API_URL/api/v1/llm-providers/credentials/$CRED_ID/models" -H "Authorization: Bearer $ARCHY_TOKEN"
# {"models": ["gpt-4o", "gpt-4o-mini", "text-embedding-3-small"], "supports_listing": true}

    Manage credentials¶

    Action Request
    List GET /llm-providers/credentials
    Get one GET /llm-providers/credentials/{id}
    Rename, rotate key or change URL PUT /llm-providers/credentials/{id} with only the fields to change
    Mark as the default of its scope POST /llm-providers/credentials/{id}/set-default
    Delete DELETE /llm-providers/credentials/{id}

    Choose the model: attachments¶

    A model attachment pins a (credential, model_name) pair to a target. There are three targets.

    Target Endpoint Effect
    Agent /llm-providers/model-attachments/agents/{agent_id} Only that agent
    Project /llm-providers/model-attachments/projects/{project_id} Agents in that project without their own attachment
    Organization /llm-providers/model-attachments/org Agents everywhere without a closer attachment

    Each target supports GET, PUT and DELETE. The credential must be verified or PUT returns 422.

    # Organization default model
curl -s -X PUT "$ARCHY_API_URL/api/v1/llm-providers/model-attachments/org" \
  -H "Authorization: Bearer $ARCHY_TOKEN" -H "Content-Type: application/json" \
  -d "{\"credential_id\": \"$CRED_ID\", \"model_name\": \"gpt-4o-mini\"}"

# A stronger model for one agent
curl -s -X PUT "$ARCHY_API_URL/api/v1/llm-providers/model-attachments/agents/$AGENT_ID" \
  -H "Authorization: Bearer $ARCHY_TOKEN" -H "Content-Type: application/json" \
  -d "{\"credential_id\": \"$CRED_ID\", \"model_name\": \"gpt-4o\"}"

    Which model runs¶

    For every execution Archy walks this list and uses the first tier that applies:

    1. Agent attachment.
    2. Agent config pin: config.model with both credential_id and model_name.
    3. Project attachment.
    4. Project platform default model (see below).
    5. Organization attachment.
    6. Organization platform default model.
    7. Legacy agent model_name with no credential. This runs on the platform's own model service, not on your credential.

    If none of these applies, the agent has no model and the call fails (or answers in echo mode, see Agents). Agents built by the platform itself fall back to the operator's default model through tier 7.

    A tier is skipped when its credential is missing or unverified. A stored credential that cannot be decrypted is an error, never a silent fallback. A project platform default model (tier 4) wins over an organization attachment (tier 5). The flow diagram shows the same logic.

    is_default does not choose the model

    The is_default flag marks a credential as the default of its scope in the credential list, but only attachments decide which model runs for organization and project defaults. Always create an attachment.

    Do not set only config.model.model_name

    An agent whose config.model has a model_name but no credential_id does not pin a model. If a project or organization attachment (or a platform default model) exists, that wins and the agent's model_name is ignored. Otherwise the agent runs model_name on the platform model service, not on your provider. To pin a model to one agent use an agent attachment, or set both credential_id and model_name.

    Platform default model overrides¶

    Organizations that use the platform's hosted model (no credential) can still pick the deployment name. These tiers, and tier 7, run only when the organization allows the platform fallback (allow_platform_llm_fallback); otherwise the call fails with a credential_error.

    Scope Endpoint
    Organization GET, PUT, DELETE /llm-providers/platform-default-model with {"model_name": "..."}
    Project .../platform-default-model/projects/{project_id}

    When nothing is configured¶

    If an organization has no usable credential and the platform fallback is disabled for it, execution fails with a clear message instead of using a shared key:

    {
  "mode": "credential_error",
  "credential_error": "No LLM provider credential is configured for this organization and platform fallback is disabled. Add an LLM provider credential ..."
}

    Add and verify a credential, attach a model, and retry. This is not an authentication error; 401 always means the bearer token is bad.

    Embeddings¶

    Knowledge bases embed text with a model from one of your credentials. Set the organization default once; each new knowledge base created without its own embedding_model copies it, so changing the default later never invalidates vectors that already exist.

    curl -s -X PUT "$ARCHY_API_URL/api/v1/llm-providers/embedding-default" \
  -H "Authorization: Bearer $ARCHY_TOKEN" -H "Content-Type: application/json" \
  -d "{\"credential_id\": \"$CRED_ID\", \"model_name\": \"text-embedding-3-small\", \"dimensions\": 1536}"
    • Providers with embeddings: azure_openai, openai, openai_compatible, ollama. DeepSeek has no embeddings endpoint.
    • GET returns the default with available: false if its credential was deleted or is no longer verified; new knowledge bases then fail until you change or clear it (DELETE).
    • A knowledge base can also name its own model: embedding_model: "connection:<credential_id>:<model_name>".

    A helper in Python¶

    import httpx


def connect_openai(client: httpx.Client, api_key: str) -> str:
    """Create, verify and attach an OpenAI credential as the organization default. Returns its id."""
    cred = client.post(
        "/api/v1/llm-providers/credentials",
        json={"provider": "openai", "display_name": "OpenAI", "api_key": api_key},
    )
    cred.raise_for_status()
    cred_id = cred.json()["id"]

    check = client.post(f"/api/v1/llm-providers/credentials/{cred_id}/verify").json()
    if not check["success"]:
        raise RuntimeError(check["error"])

    for url, body in (
        ("/api/v1/llm-providers/model-attachments/org", {"credential_id": cred_id, "model_name": "gpt-4o-mini"}),
        (
            "/api/v1/llm-providers/embedding-default",
            {"credential_id": cred_id, "model_name": "text-embedding-3-small", "dimensions": 1536},
        ),
    ):
        client.put(url, json=body).raise_for_status()
    return cred_id

    Security notes¶

    • Keys are encrypted with AES-256-GCM. Each credential records the key_id it was encrypted under, so operators can rotate encryption keys without downtime.
    • Responses and logs never include the key. Provide it only when creating or rotating.
    • base_url values are validated against SSRF rules before any request leaves the platform.
    • Credentials are tenant scoped. An organization can never resolve another organization's credential.
