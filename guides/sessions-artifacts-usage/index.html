    Sessions, artifacts and usage¶

    Sessions¶

    A session is the persisted record of a conversation with an agent or a run of a workflow: messages, tool calls, retrievals, errors and the per-node trace of workflow runs.

    All paths start with /api/v1/orgs/{org_id}/projects/{project_id}.

    Action Request
    List sessions (agent and workflow) GET .../sessions?limit=50&offset=0
    Read one with its history GET .../sessions/{session_id}
    Activity events (tool calls, retrievals, errors) GET .../sessions/{session_id}/activity
    Files created during the session GET .../sessions/{session_id}/artifacts
    Rename PATCH .../sessions/{session_id}/rename
    Generate a name from the content POST .../sessions/{session_id}/regenerate-name
    Delete DELETE .../sessions/{session_id}
    Sessions that involved an agent GET /api/v1/agents/orgs/{org_id}/projects/{project_id}/agents/{agent_id}/sessions
    Workflow sessions GET .../workflows/{workflow_id}/sessions (optional status filter)
    One workflow session with its trace GET .../workflows/{workflow_id}/sessions/{session_id} 
    curl -s "$BASE/sessions?limit=20" -H "Authorization: Bearer $ARCHY_TOKEN"

    [
  {
    "session_id": "4e7c87f4-30d4-565f-a47b-9b4fca7f385a",
    "created_at": "2026-11-17T09:09:03",
    "updated_at": "2026-11-17T09:12:44",
    "name": "Refund policy question",
    "last_agent_id": "26fc2a0e-afe5-4c01-849b-eac03777464e"
  }
]

    Workflow sessions expose a status: completed, awaiting_input (paused at a checkpoint), failed (a checkpoint failed, for example expired) or cancelled. Note that completed only means "no waiting, failed or cancelled marker".

    Build an audit view

    Combine GET .../sessions/{id} (messages), .../activity (tool calls and retrievals) and, for workflows, the session trace to show users exactly what an agent did and why.

    Artifacts¶

    An artifact is a file stored with a project: the output of a save-file or storage-read node, an export of a run, or an upload.

    flowchart LR
    RUN[Workflow run] -->|save-file node| ART[(Artifact)]
    RUN -->|export run output| ART
    UP[Your upload] --> ART
    ART --> DL[Download]
    ART --> NODE[Later node: nodes.x.files]

    Upload¶

    curl -s -X POST "$BASE/artifacts" \
  -H "Authorization: Bearer $ARCHY_TOKEN" \
  -F "file=@report.pdf" -F "name=weekly-report.pdf" -F "media_type=application/pdf"

    Optional form fields link the file to its origin: run_id, session_id, node_id (up to 255 characters) and agent_id.

    List, read, download, delete¶

    # Filter by run, node, session, media type or source
curl -s "$BASE/artifacts?run_id=$RUN_ID&limit=50" -H "Authorization: Bearer $ARCHY_TOKEN"

# Metadata: name, media type, size, sha256, source, expiry
curl -s "$BASE/artifacts/$ARTIFACT_ID" -H "Authorization: Bearer $ARCHY_TOKEN"

# Download (always served as an attachment)
curl -s -o report.pdf "$BASE/artifacts/$ARTIFACT_ID/download" -H "Authorization: Bearer $ARCHY_TOKEN"

# Delete (soft delete; the stored blob is removed within 24 hours)
curl -s -X DELETE "$BASE/artifacts/$ARTIFACT_ID" -H "Authorization: Bearer $ARCHY_TOKEN"

    Export a run's output as a file¶

    After a run finishes, turn its final output (or one node's output) into a file:

    POST .../workflows/{workflow_id}/runs/{run_id}/exports

    The response is the new artifact. Supported formats include markdown, text, json, html, csv, docx and xlsx.

    Limits¶

    Defaults are set by the operator and can differ per deployment.

    Limit Default
    File size 25 MB
    Files per run 100
    Storage per project 1 GB
    Storage per organization 2 GB
    Retention 90 days

    Exceeding a limit returns an error naming the limit.

    Token usage¶

    Every model call records its token usage. Query it at project or organization level.

    Question Project endpoint Organization endpoint
    Totals grouped by something GET .../token-usage/aggregations GET /api/v1/orgs/{org_id}/token-usage/aggregations
    Per model GET .../token-usage/metrics/by-model GET /api/v1/orgs/{org_id}/token-usage/metrics/by-model
    Over time GET .../token-usage/metrics/timeseries GET /api/v1/orgs/{org_id}/token-usage/metrics/timeseries
    Chart ready data GET .../token-usage/charts GET /api/v1/orgs/{org_id}/token-usage/charts
    Individual events GET .../token-usage/events 
    curl -s "$BASE/token-usage/aggregations?group_by=model&token_type=total" \
  -H "Authorization: Bearer $ARCHY_TOKEN"

    {"group_by": "model", "token_type": "total", "items": []}

    Query parameters of aggregations:

    Parameter Values
    group_by model, provider, agent, workflow, project, day, week, month
    token_type input, output, total
    since, until Time window
    model, models, agent_id, workflow_id, session_id Filters
    period last_7d, last_30d or last_90d
    order_by, order_dir tokens, calls or group; asc or desc
    min_tokens, max_tokens, limit, offset Thresholds and paging (limit 1 to 200)

    The timeseries endpoint takes granularity of day or hour and returns buckets with call_count, prompt_tokens and completion tokens.

    Use usage data for showback and quotas in your product: group by agent or workflow to attribute cost, and poll the timeseries to alert on spikes.
