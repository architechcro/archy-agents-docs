    Knowledge bases¶

    A knowledge base (KB) is a collection of documents that Archy splits into chunks, embeds with your embedding model and stores in a vector index. Agents and your own code retrieve the most relevant chunks for a question (retrieval-augmented generation, RAG).

    flowchart LR
    SRC[Files, URLs, Confluence] --> ING[Ingest]
    ING --> ST[(Object storage)]
    ING --> JOB[Indexing job]
    JOB --> CH[Extract and chunk]
    CH --> EMB[Embed]
    EMB --> VEC[(Vector index)]
    Q[Question] --> RET[Retrieve top-k]
    VEC --> RET
    RET --> AG[Agent or your code]

    Before you start

    You need a verified LLM credential and an embedding default, or a KB with its own embedding_model. All paths below start with /api/v1/orgs/{org_id}/projects/{project_id}.

    BASE="$ARCHY_API_URL/api/v1/orgs/$ORG_ID/projects/$PROJECT_ID"

    Create a knowledge base¶

    curl -s -X POST "$BASE/knowledge-bases" \
  -H "Authorization: Bearer $ARCHY_TOKEN" -H "Content-Type: application/json" \
  -d '{"name": "handbook", "description": "Company handbook"}'

    {
  "id": "7da160d1-8924-4b11-8442-6bd722deccc8",
  "project_id": "f834cf48-7bf7-4489-8b4b-9c7d8c832cb5",
  "name": "handbook",
  "description": "Company handbook",
  "embedding_model": "connection:864beb2b-32f1-4ee1-aa0c-ccdd1ba34948:text-embedding-3-small",
  "vector_store_config": {"dimensions": 1536}
}

    With an organization embedding default the response shows the copied connection:<credential_id>:<model> value and may add the vector dimensions. Without a default both are null.

    Field Meaning
    name 1 to 255 characters
    description Optional
    embedding_model Optional. Defaults to the organization embedding default. Use connection:<credential_id>:<model_name> to pin one.
    vector_store_config Optional vector store options, for example the vector dimensions

    Choose the embedding model before you add documents. Vectors made with one model cannot be searched with another.

    Add documents¶

    Upload files¶

    curl -s -X POST "$BASE/knowledge-bases/$KB_ID/documents/upload" \
  -H "Authorization: Bearer $ARCHY_TOKEN" \
  -F "files=@handbook.pdf" -F "files=@faq.md"

    Supported types: .txt, .md, .json, .html, .htm, .pdf, .docx, .xlsx, .pptx, .png, .jpg, .jpeg. Other extensions (for example .csv, .doc, .xls, .ppt) are rejected with 400 Unsupported file type. Each file may be up to 50 MB. An unsupported type or an oversized file is rejected for the whole request.

    The response lists the created documents, normally with status: "uploaded", and indexing is queued automatically. Without a job queue the upload indexes synchronously before it returns, so a document can already be indexed or failed.

    Import from URLs¶

    curl -s -X POST "$BASE/knowledge-bases/$KB_ID/documents/from-urls" \
  -H "Authorization: Bearer $ARCHY_TOKEN" -H "Content-Type: application/json" \
  -d '{"urls": ["https://example.com/pricing", "https://example.com/terms"]}'

    You can send up to 20 URLs. The response is a partial success: documents for the pages that were fetched and errors (url and detail) for the ones that failed. URLs pass the same SSRF validation as every outbound request.

    Import from Confluence¶

    Confluence pages are read with a personal Atlassian connection that you create once (see Connections and integrations). Pass its id:

    curl -s -X POST "$BASE/knowledge-bases/$KB_ID/documents/from-confluence" \
  -H "Authorization: Bearer $ARCHY_TOKEN" -H "Content-Type: application/json" \
  -d "{\"integration_id\": \"$INTEGRATION_ID\", \"page_urls\": [\"https://acme.atlassian.net/wiki/spaces/ENG/pages/123/Runbook\"], \"include_children\": true, \"max_depth\": 3}"

    For large spaces use the background import (POST .../confluence-imports) and refresh later with POST .../sources/{source_id}/confluence-sync. Each import is tracked as a source; GET .../sources lists them and POST .../sources/{source_id}/sync re-syncs one.

    Index¶

    After an upload Archy indexes each document in the background. You can also drive it yourself.

    Goal Request
    Index every document (async) POST .../knowledge-bases/{kb}/index
    Index every document and wait POST .../knowledge-bases/{kb}/index-sync
    Index one document (async job) POST .../documents/{doc}/index-jobs
    Poll one job GET .../documents/{doc}/index-jobs/{job}
    Summary of the whole KB GET .../knowledge-bases/{kb}/stats 
    curl -s "$BASE/knowledge-bases/$KB_ID/stats" -H "Authorization: Bearer $ARCHY_TOKEN"

    {"files_total": 12, "indexed_total": 10, "indexing_total": 2}

    A job has status queued, running, succeeded or failed; a failed job reports error_type and error_message. A document's own status moves uploaded, indexing, indexed or failed. POST .../index re-queues every document of the knowledge base (each document has at most one job, which is reset) and returns 503 when the queue is unavailable. POST .../index-sync processes only documents that are not yet indexed and waits for the result.

    Query¶

    curl -s -X POST "$BASE/knowledge-bases/$KB_ID/query" \
  -H "Authorization: Bearer $ARCHY_TOKEN" -H "Content-Type: application/json" \
  -d '{"query": "How long do I have to ask for a refund?", "top_k": 5, "retrieval_strategy": "hybrid"}'

    {
  "kb_id": "7da160d1-8924-4b11-8442-6bd722deccc8",
  "query": "How long do I have to ask for a refund?",
  "results": [
    {
      "chunk_id": "c1f0...",
      "score": 0.83,
      "content": "Refunds are available within 30 days of purchase with a receipt.",
      "metadata": {"filename": "handbook.md"}
    }
  ]
}
    Field Values
    query 1 to 20,000 characters
    top_k 1 to 50, default 5
    retrieval_strategy hybrid (default: vector plus lexical), vector (similarity only), graph (expands results by shared entities for multi-hop questions)

    Use a knowledge base from an agent¶

    Set the KB in the agent config. The agent retrieves context before it answers.

    {
  "name": "support-assistant",
  "config": {
    "sys_prompt": "Answer only from the knowledge base. Say when you do not know.",
    "knowledge_base_id": "7da160d1-8924-4b11-8442-6bd722deccc8",
    "knowledge_base_top_k": 4
  }
}

    POST .../agents/{agent_id}/query with {"kb_id", "query", "top_k", "min_score"} is a retrieval preview, not a model call: it streams NDJSON events agent_start, retrieval (the retrieved chunks) and agent_final, whose response joins the retrieved chunks. It does not use the agent's model or configuration. To get a model answer, query the agent normally (Running and streaming).

    Manage¶

    Action Request
    List knowledge bases GET .../knowledge-bases
    Usage across knowledge bases GET .../knowledge-bases/usage
    List documents GET .../knowledge-bases/{kb}/documents
    Delete a document DELETE .../knowledge-bases/{kb}/documents/{doc}
    Export metadata, sources and documents GET .../knowledge-bases/{kb}/export
    Delete a knowledge base DELETE .../knowledge-bases/{kb}

    Python: upload and wait¶

    import time
import httpx


def add_files_and_wait(client: httpx.Client, scope: str, kb_id: str, paths: list[str], timeout: int = 600) -> dict:
    files = [("files", (p.rsplit("/", 1)[-1], open(p, "rb"))) for p in paths]
    client.post(f"{scope}/knowledge-bases/{kb_id}/documents/upload", files=files).raise_for_status()

    deadline = time.time() + timeout
    while time.time() < deadline:
        stats = client.get(f"{scope}/knowledge-bases/{kb_id}/stats").json()
        if stats["indexing_total"] == 0 and stats["files_total"] > 0:
            return stats
        time.sleep(2)
    raise TimeoutError("indexing did not finish")


# scope = f"/api/v1/orgs/{org_id}/projects/{project_id}"

    If indexed_total is lower than files_total after indexing_total reaches 0, some documents failed: list them with GET .../documents and look at status.

    Practices that improve answers¶

    • One knowledge base per subject. Mixing unrelated material lowers precision. Attach several KBs through workflows when an agent needs more than one.
    • Test retrieval first. Call /query with real questions and read the chunks before you blame the agent prompt.
    • Keep top_k small. 3 to 8 chunks is usually enough; more adds noise and cost.
    • Prefer text-rich sources. Scanned images contain less retrievable text than PDFs with a text layer.
    • Do not change the embedding model of a populated KB. Create a new KB and re-ingest instead.
    • Tell the agent what to do when the answer is missing. "Say you do not know" in the system prompt prevents invented answers.
