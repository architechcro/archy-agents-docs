    Connect a client¶

    Pick the setup that matches your client. The hosted HTTP server is the easiest: no checkout, and OAuth clients sign in without copying a token.

    Option Needs Best for
    Hosted server with OAuth A client that supports remote MCP with OAuth Claude, ChatGPT, VS Code, Cursor, Windsurf
    Hosted server with an API key An archy_mcp_ key Clients without OAuth, scripts, CI
    Local stdio server The repository and Python 3.11+ Offline development, custom builds

    Client configuration formats change

    The snippets below show the shape each client expects at the time of writing. Check your client's documentation if a key name differs.

    Prerequisite: an LLM credential¶

    Tools that run agents need the organization to have a verified LLM credential and an attached model. Without one, agent calls return a clear credential_error; see LLM providers and models. Tools that only read or store data (listing, searching, uploading) do not need one.

    Hosted server with OAuth¶

    Point the client at the MCP URL:

    https://archy-mcp-server.fly.dev/mcp

    The client then performs this standard flow on its own:

    1. It calls the server without a token and receives 401 with a WWW-Authenticate header that names resource_metadata.
    2. It reads /.well-known/oauth-protected-resource/mcp, which names the Archy API as the authorization server.
    3. It reads /.well-known/oauth-authorization-server on the API and registers itself with POST /oauth/register (dynamic client registration, RFC 7591).
    4. It sends you to /oauth/authorize with PKCE (S256). You sign in and approve the requested scope (mcp:tools, or mcp:read when the client registered with it).
    5. It exchanges the code at /oauth/token and calls the server with the access token.

    The hosted API allows Claude (claude.ai, claude.com), ChatGPT (chatgpt.com, chat.openai.com, platform.openai.com), vscode.dev, insiders.vscode.dev and the schemes cursor, vscode, vscode-insiders and windsurf; loopback redirects are always allowed. A self-hosted API allows only loopback until the operator sets OAUTH_REDIRECT_URI_ALLOWLIST (origins) and OAUTH_REDIRECT_SCHEME_ALLOWLIST (schemes), both JSON lists, and OAUTH_ISSUER_URL.

    .vscode/mcp.json:

    {
  "servers": {
    "archy": {
      "type": "http",
      "url": "https://archy-mcp-server.fly.dev/mcp"
    }
  }
}

    Open the Command Palette, run MCP: List Servers, start archy and follow the sign-in prompt.

    claude mcp add --transport http archy https://archy-mcp-server.fly.dev/mcp

    Then run /mcp inside Claude Code to authenticate.

    Add a custom connector (remote MCP server) in the product's settings and enter the URL. Both complete the OAuth flow in the browser.

    ~/.cursor/mcp.json:

    {
  "mcpServers": {
    "archy": { "url": "https://archy-mcp-server.fly.dev/mcp" }
  }
}

    Hosted server with an API key¶

    Create a key in a project (it is shown once):

    curl -s -X POST "$ARCHY_API_URL/api/v1/orgs/$ORG_ID/projects/$PROJECT_ID/mcp-tokens" \
  -H "Authorization: Bearer $ARCHY_TOKEN" -H "Content-Type: application/json" \
  -d '{"name": "my-ide", "expires_in_days": 90}'

    Send it as a bearer token on every request:

    {
  "servers": {
    "archy": {
      "type": "http",
      "url": "https://archy-mcp-server.fly.dev/mcp",
      "headers": { "Authorization": "Bearer ${input:archy_key}" }
    }
  },
  "inputs": [
    { "id": "archy_key", "type": "promptString", "description": "Archy MCP key (archy_mcp_...)", "password": true }
  ]
}

    {
  "mcpServers": {
    "archy": {
      "url": "https://archy-mcp-server.fly.dev/mcp",
      "headers": { "Authorization": "Bearer archy_mcp_..." }
    }
  }
}

    Use the official SDK; see Build with the MCP SDK.

    How the hosted server treats a key:

    • The server validates it against the API and binds the request to the org, project and scope stored with the key. Nothing in the request can change them.
    • Validations are cached for at most MCP_KEY_CACHE_TTL_SECONDS (default and maximum 60 seconds), for the MCP server's own check. The API checks the key again on every forwarded call, so tool calls with a revoked key fail at once.
    • The API accepts a key only on a reviewed list of routes used by the agent, knowledge base, RAG, workflow, session, artifact, connection, MCP server and skill tools. Any other route returns 401 Invalid token, so the usage, plans, dialogs, research, Confluence and organization or project listing tools do not work with a key (use a user JWT).
    • A deactivated creator invalidates the key.

    API key scopes¶

    Scope Allows
    mcp:tools Read and write tools. Default for keys created with POST .../mcp-tokens.
    mcp:read Read-only tools. An OAuth client gets it when it registered with that scope.
    mcp:admin Reserved. Treated as write-capable, but neither the API nor OAuth issues it.

    A scope that is empty or unknown is treated as read-only. Through MCP tools a write attempt with a read scope fails with [FORBIDDEN] Token scope mcp:read does not allow this operation; the REST API returns 403 Token scope does not allow this operation for the same key.

    Local stdio server¶

    The client starts the server as a child process. You need the repository and a token.

    git clone <your archy-agents-scope repository url>
cd archy-agents-scope
poetry install
poetry run which python        # note this path

    Every client uses the same four settings:

    Setting Value
    Command the repository's .venv/bin/python (absolute path)
    Args ["-m", "src.mcp_server"]
    Working directory the repository root (required, otherwise No module named 'src')
    Environment ARCHY_API_URL (your API) and ARCHY_MCP_TOKEN (an archy_mcp_ key or a JWT) 
    {
  "servers": {
    "archy": {
      "type": "stdio",
      "command": "/path/to/archy-agents-scope/.venv/bin/python",
      "args": ["-m", "src.mcp_server"],
      "cwd": "/path/to/archy-agents-scope",
      "env": {
        "ARCHY_API_URL": "http://localhost:8000",
        "ARCHY_MCP_TOKEN": "${input:archy_key}"
      }
    }
  },
  "inputs": [
    { "id": "archy_key", "type": "promptString", "description": "Archy MCP key", "password": true }
  ]
}

    ~/Library/Application Support/Claude/claude_desktop_config.json on macOS, %APPDATA%\Claude\claude_desktop_config.json on Windows:

    {
  "mcpServers": {
    "archy": {
      "command": "/path/to/archy-agents-scope/.venv/bin/python",
      "args": ["-m", "src.mcp_server"],
      "cwd": "/path/to/archy-agents-scope",
      "env": { "ARCHY_API_URL": "http://localhost:8000", "ARCHY_MCP_TOKEN": "archy_mcp_..." }
    }
  }
}

    Use the same JSON as Claude Desktop in ~/.cursor/mcp.json (or .cursor/mcp.json), ~/.codeium/windsurf/mcp_config.json, or Cline's cline_mcp_settings.json.

    In stdio mode the key is validated once at startup. Reload the server entry after any config change.

    Verify the connection¶

    Ask the client to run these tools in order:

    1. auth_whoami: shows the organization, project and subject the server resolved from the credential (it makes no API call).
    2. kb_list: lists knowledge bases, which confirms that the API accepts the credential.
    3. rag_search: searches one.

    Or check a key directly:

    curl -s -X POST "$ARCHY_API_URL/api/v1/internal/mcp-tokens/validate" \
  -H "Content-Type: application/json" -d '{"token": "archy_mcp_..."}'

    Outside local development this internal endpoint requires the X-Internal-Secret header, so prefer the tools above.

    Troubleshooting¶

    Symptom Cause Fix
    No module named 'src' cwd not set or wrong interpreter Set cwd to the repository root and use its .venv/bin/python
    httpx.ConnectError The API is not running or ARCHY_API_URL is wrong Start the API and fix the URL
    Hosted: 401 Invalid or expired MCP API key. stdio: startup fails with MCP API key validation failed (HTTP 401) The key is unknown, expired, revoked or belongs to another environment Create a new key against the API you connect to
    [INVALID_REQUEST] Invalid token from a tool The tool's route is not on the API key route list Use a user JWT for that tool
    401 Missing Authorization header An HTTP request had no bearer token Send Authorization: Bearer ... on every request
    401 Token validation service unavailable The hosted server cannot reach the API, or the API returned a 5xx while validating an API key Check ARCHY_API_URL and API health
    [FORBIDDEN] Token scope mcp:read does not allow this operation (REST: 403 Token scope does not allow this operation) A read-only credential used a write tool Use a mcp:tools credential
    Tools missing after a change The client did not reload Restart the server entry or the client
    credential_error from an agent tool The organization has no verified LLM credential Connect a provider
    Browser clients blocked by CORS CORS is off by default The operator sets MCP_CORS_ORIGINS

    Security notes¶

    • Treat archy_mcp_ keys like passwords: use secure prompts, never commit them, revoke keys you no longer use (POST .../mcp-tokens/{token_id}/revoke).
    • Prefer OAuth for people and short-lived keys for automation.
    • Expose only the tool modules a client needs with MCP_ENABLED_TOOLS on your own deployment.
