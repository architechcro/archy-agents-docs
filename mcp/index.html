    MCP¶

    The Model Context Protocol (MCP) is an open standard that lets AI applications use tools. Archy exposes its capabilities through an MCP server, so an AI client can create agents, search knowledge bases, run workflows and read results in natural language or in code.

    Two directions

    • This section: AI clients and agents call Archy through its MCP server.
    • External MCP servers and skills: Archy agents call other MCP servers as tools.
    flowchart LR
    subgraph Clients
        C1[Claude]
        C2[VS Code Copilot]
        C3[Cursor, Windsurf, Cline]
        C4[ChatGPT]
        C5[Your agent with the MCP SDK]
    end
    C1 & C2 & C3 & C4 & C5 -->|MCP| S[Archy MCP server]
    S -->|REST, caller token| API[Archy API]

    What you get¶

    • Dozens of tools across agents, knowledge bases, RAG search and upload, workflows (including authoring and validation), sessions, artifacts, usage, plans, dialogs, research, Confluence, GitHub and more. See the Tool catalog, which is generated from the server.
    • Prompts that guide a client through designing, converting and repairing a workflow.
    • Resources with the workflow node types, definition schema, validation codes and authoring guide, so an agent can read the contracts before it writes a graph.

    Transports¶

    Transport Start Use when
    stdio (default) python -m src.mcp_server An IDE or desktop app launches the server as a local process
    streamable-http MCP_TRANSPORT=streamable-http python -m src.mcp_server A hosted server that many clients reach over HTTPS at /mcp
    sse MCP_TRANSPORT=sse ... Older clients that only speak SSE

    The hosted server is at https://archy-mcp-server.fly.dev/mcp. A local compose stack serves http://localhost:8001/mcp. GET /health and the protected resource metadata (/.well-known/oauth-protected-resource/...) are public; everything else needs credentials.

    Authentication¶

    Credential Where Notes
    OAuth 2.0 with PKCE Hosted server, clients that support it (Claude, ChatGPT, VS Code, Cursor, Windsurf) The client discovers the authorization server, registers itself and asks the user to sign in. No token to copy.
    archy_mcp_ API key Any client Create with POST .../mcp-tokens. Bound to one project. Works only on a reviewed list of tool routes (see the note below).
    User JWT Hosted HTTP or stdio A project-scoped REST API token (it must carry org_id and project_id). Works with every tool.

    Every HTTP request must carry Authorization: Bearer <credential>. A request without it receives 401 and a WWW-Authenticate header that points to the protected resource metadata, which is how OAuth clients start the flow:

    HTTP/1.1 401 Unauthorized
www-authenticate: Bearer scope="mcp:tools", resource_metadata="https://archy-mcp-server.fly.dev/.well-known/oauth-protected-resource/mcp"

    API keys and OAuth tokens cover a subset of tools

    OAuth access tokens are archy_mcp_ keys, and the API accepts such a key only on a reviewed list of routes: agents, knowledge bases and RAG, workflows, sessions, artifacts, connections, MCP servers and skills. Tools for usage, plans, dialogs, research, Confluence and listing organizations and projects call other routes, so they answer [INVALID_REQUEST] Invalid token with a key or an OAuth token and need a user JWT.

    The org and project of each call always come from the credential, per request. Two clients with different credentials can never reach each other's data.

    Details and per-client setup: Connect a client.

    Read-only access¶

    A credential with scope mcp:read can call only read tools. Anything that writes (create, update, delete, execute) is refused with a clear error. API keys created with the REST API get mcp:tools (read and write). An OAuth client can request mcp:read if it included that scope in the scope it sent to POST /oauth/register; otherwise it gets mcp:tools.

    Example: a conversation with tools¶

    You: Which knowledge bases do we have, and does any of them mention refunds?

    Client calls kb_list, then rag_search with knowledge_base_id and query: "refund policy".

    Client answers from the returned chunks and cites the source file names.

    You: Create an agent called "refund-helper" that answers from the handbook knowledge base.

    Client calls agent_create with name, system_prompt and knowledge_base_ids, then agent_query to test it.

    Errors¶

    Tool errors carry a code and the API's message:

    API status MCP error code
    400, 404, 409, 422 INVALID_PARAMS
    401, 403 INVALID_REQUEST
    429, 5xx and any other status INTERNAL_ERROR
    Refused locally for a read-only credential FORBIDDEN

    Some tools also return NOT_FOUND or INVALID_PARAMS before they call the API. The text is [CODE] message. Coded API errors keep their JSON shape inside the message, for example CONVERSION_LOSSES when converting a workflow.

    Server configuration¶

    Variable Default Meaning
    ARCHY_API_URL http://localhost:8000 The Archy API the server calls
    ARCHY_MCP_TOKEN empty Credential used by the stdio transport. HTTP transports never use it.
    MCP_TRANSPORT stdio stdio, streamable-http or sse
    MCP_HTTP_HOST, MCP_HTTP_PORT 0.0.0.0, 8001 HTTP bind address
    MCP_ENABLED_TOOLS all Comma separated tool module names to expose. Valid names: agents, artifacts, auth_tools, confluence, confluence_write, connections, dialog, github, health, kb, mcp_registry, plans, rag, research, sessions, skills, usage, workflow_authoring, workflows. Unknown names are ignored. Include workflow_authoring for the workflow prompts and resources and auth_tools for auth_whoami.
    MCP_CORS_ORIGINS none Allowed browser origins (a bare * is ignored)
    MCP_KEY_CACHE_TTL_SECONDS 60 How long a validated API key is reused (0 to 60). Bounds how long a revoked key keeps working.
    INTERNAL_VALIDATE_SECRET empty Shared secret with the API for validating API keys. Required in production: set it to the same value on the API and on the MCP server, or every API key and OAuth token is refused.
    ARCHY_API_PUBLIC_URL ARCHY_API_URL Public origin of the API advertised in OAuth discovery. Set it to the same value as the API's OAUTH_ISSUER_URL.
    MCP_PUBLIC_URL built from the request headers Public origin of the MCP server advertised in OAuth discovery
    MCP_LOG_LEVEL INFO Log level

    Reduce risk by exposing only the modules a client needs with MCP_ENABLED_TOOLS.
