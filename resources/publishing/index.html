    Publishing this site¶

    This page is for the maintainers of the documentation. The site is a static MkDocs Material build that lives in the developer-docs/ folder of the archy-agents-scope repository.

    The site is published at https://architechcro.github.io/archy-agents-docs/ from the public repository architechcro/archy-agents-docs (branch gh-pages, GitHub Pages). Publish a new version with:

    DOCS_SITE_URL=https://architechcro.github.io/archy-agents-docs \
  developer-docs/publish.sh https://github.com/architechcro/archy-agents-docs.git

    What is generated and what is written¶

    Content Source Regenerate with
    Guides, tutorials, architecture, concepts Markdown in developer-docs/docs/ Edit the files
    openapi.json The FastAPI app poetry run python scripts/export_openapi.py
    MCP tool catalog The MCP server (tools, prompts, resources) The same command
    API reference pages and schemas developer-docs/openapi/openapi.json Built by hooks/gen_reference.py during mkdocs build
    llms.txt, llms-full.txt The hand-written pages Built by hooks/gen_llms.py

    The two JSON snapshots in developer-docs/openapi/ are committed. A test (tests/test_developer_docs.py) fails when they are stale, so an endpoint or tool change cannot merge without refreshing them.

    Public specification

    scripts/export_openapi.py removes operator-only route groups (platform administration, operations console, sandbox, promotions, environment transitions) from the public document. Change EXCLUDED_TAGS in that script to adjust it.

    Build locally¶

    cd developer-docs
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
mkdocs serve                      # live preview on http://127.0.0.1:8000
mkdocs build --strict             # the CI build; writes developer-docs/site/

    --strict turns warnings (broken links, missing anchors, unknown nav entries) into failures. Set DOCS_SITE_URL to the final public address before a production build so that llms.txt contains absolute links and the sitemap is correct:

    DOCS_SITE_URL=https://docs.example.com mkdocs build --strict

    Update after an API change¶

    poetry run python scripts/export_openapi.py        # refresh both snapshots
poetry run pytest tests/test_developer_docs.py     # confirm they are current
cd developer-docs && mkdocs build --strict

    Review the diff of developer-docs/openapi/openapi.json: it is the API change log. If you changed behavior that a guide describes, update the guide too.

    Hosting options¶

    The output is plain static files, so any static host works.

    Option Notes
    GitHub Pages from a public docs repository GitHub Pages is not available for private repositories on the GitHub Team plan, so publish the built site to a separate public repository. developer-docs/publish.sh automates this.
    GitHub Pages from this repository Possible only when the repository is public or the organization has a plan that supports Pages on private repositories. The workflow .github/workflows/docs.yml includes a Pages deployment job guarded by a repository variable.
    Cloudflare Pages Upload developer-docs/site/ with wrangler pages deploy developer-docs/site.
    Any object storage or CDN Sync developer-docs/site/ to a bucket with static website hosting.

    Publish to a public repository (GitHub Pages)¶

    One-time setup:

    1. Create an empty public repository, for example archy-agents-docs.
    2. In its settings, enable Pages and choose the gh-pages branch, folder / (root).
    3. Optionally add a custom domain.

    Publish from your machine:

    DOCS_SITE_URL=https://<owner>.github.io/archy-agents-docs \
  developer-docs/publish.sh git@github.com:<owner>/archy-agents-docs.git

    The script requires DOCS_SITE_URL, builds the site in strict mode, clones the gh-pages branch of the target (or starts it if it does not exist), replaces its contents with the new build, keeps an existing CNAME, adds .nojekyll, commits and pushes. It never rewrites history and stops if the target cannot be reached.

    Publish from CI¶

    .github/workflows/docs.yml builds the site on every pull request that touches the documentation. On pushes to main it can publish in two ways. Both are off until you configure them:

    Repository setting Effect
    Variable DOCS_PUBLISH_REPO (for example owner/archy-agents-docs) and secret DOCS_PUBLISH_TOKEN (a token with write access to that repository) Push the build to the gh-pages branch of the public repository
    Variable DOCS_PAGES_ENABLED set to true Deploy with GitHub Pages from this repository

    Set DOCS_SITE_URL as a repository variable as well.

    Content standards¶

    • Write for two readers: a developer who skims and an agent that reads literally. Prefer short sections, tables and runnable examples.
    • Every example must be correct. Run it against a local stack or the in-process test app before you commit it.
    • Never include real tokens, keys, customer data or internal hostnames. Use placeholders.
    • Describe behavior the code guarantees. If you are unsure, read the code or test it, then document what you saw.
    • Keep terminology consistent: organization, project, agent, knowledge base, workflow, run, session, artifact.
