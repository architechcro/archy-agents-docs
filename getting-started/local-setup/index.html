    Run Archy locally¶

    You can run the full platform on your machine in a few minutes. This is the recommended way to learn the API and to develop against it.

    What you need¶

    • Docker with Compose v2
    • curl and jq
    • Optional, for service tokens and the dev loop: Python 3.11 or 3.12 and Poetry
    • An API key for an LLM provider (OpenAI, Azure OpenAI, Anthropic, Gemini, Groq, DeepSeek or a local Ollama). You add it through the API later; nothing is baked into the stack.

    Start the stack¶

    1. Create the credential encryption key¶

    Archy encrypts every stored LLM provider API key with AES-256-GCM. The key is required: without it, creating an LLM credential fails. Generate a 32 byte base64 key once and keep it. If you lose it, stored credentials can no longer be decrypted.

    export LLM_CREDENTIAL_ENCRYPTION_KEY="$(openssl rand -base64 32)"

    The stock docker-compose.yml does not forward this variable, so add a docker-compose.override.yml next to it. Compose merges it automatically:

    services:
  api:
    environment:
      LLM_CREDENTIAL_ENCRYPTION_KEY: ${LLM_CREDENTIAL_ENCRYPTION_KEY}
      # Only when you want to use a model server on your machine, for example Ollama.
      # SSRF_ALLOW_LOCAL_URLS: "true"

    2. Start the services¶

    git clone <your archy-agents-scope repository url>
cd archy-agents-scope
docker compose up -d --build

    Compose starts these services:

    Service Port Purpose
    api 8000 The REST API. Runs database migrations on start.
    mcp-server 8001 The Archy Platform MCP server (streamable HTTP).
    postgres 5453 Metadata (organizations, projects, agents, workflows, sessions).
    qdrant 6333 Vector store for knowledge bases.
    redis 6379 Cache and queues.
    minio 9000, 9001 S3-compatible object storage for uploaded documents.

    Check that the API is healthy:

    curl -s http://localhost:8000/health
curl -s http://localhost:8000/health/readiness

    Open the interactive API explorer at http://localhost:8000/docs.

    Defaults are for development only

    The stack signs tokens with JWT_SECRET_KEY=change-me. Never use the default outside your machine. Set your own value in the environment before docker compose up.

    Create a service token¶

    Provisioning endpoints need a service token. In production the operator of your deployment issues it. Locally you mint one with the same signing secret the API uses:

    JWT_SECRET_KEY=change-me poetry run python scripts/generate_service_token.py \
  --subject my-backend \
  --scopes provision:org provision:project provision:user provision:user:read \
  --expires-in-minutes 120

    Export the output:

    export SERVICE_TOKEN="<printed token>"
export ARCHY_API_URL=http://localhost:8000

    The command prints only the token. Service tokens carry scopes, not a tenant: the target organization is part of each request.

    Why a service token?

    A self-registered user cannot manage organization-level settings such as LLM credentials, and only a service token can create organizations with chosen ids. The Quickstart uses the service token once to create an organization and an admin, then continues with that admin's user token.

    The development loop¶

    If you prefer to run the API on the host and only the dependencies in Docker:

    docker compose up -d postgres qdrant redis minio minio-init
cp .env.example .env.local        # local development loads .env.local
# add LLM_CREDENTIAL_ENCRYPTION_KEY=<base64 key> to .env.local
poetry install
poetry run alembic upgrade head
poetry run uvicorn src.main:app --reload --port 8000

    .env.local points DATABASE_URL at localhost:5433. Compose publishes Postgres on 5453. Update DATABASE_URL to the port you use.

    Run the MCP server on the host:

    export ARCHY_API_URL=http://localhost:8000
export ARCHY_MCP_TOKEN="<MCP API key>"      # see the MCP guide
poetry run python -m src.mcp_server

    Stop and reset¶

    docker compose down          # stop, keep data
docker compose down -v       # stop and delete all data

    Configuration reference¶

    The settings you are most likely to change. All are environment variables.

    Variable Default Purpose
    DATABASE_URL local Postgres SQLAlchemy URL of the metadata database
    QDRANT_URL http://localhost:6333 Vector store
    REDIS_URL redis://localhost:6379/0 Cache and queues
    S3_ENDPOINT_URL, S3_ACCESS_KEY_ID, S3_SECRET_ACCESS_KEY, S3_BUCKET_NAME MinIO in compose Document storage
    JWT_SECRET_KEY, JWT_ALGORITHM change-me, HS256 Signing of user and service tokens
    EXTERNAL_AUTH_ENABLED, EXTERNAL_AUTH_ISSUER, EXTERNAL_AUTH_AUDIENCE, EXTERNAL_AUTH_JWKS_URL off Accept tokens from your identity provider
    SERVICE_TOKEN_BINDING_MODE audit enforce requires service tokens to name the organizations they may act for
    LLM_CREDENTIAL_ENCRYPTION_KEY none, required Base64 32 byte key that encrypts stored provider API keys. Optional rotation: LLM_CREDENTIAL_ENCRYPTION_KEYS and LLM_CREDENTIAL_ENCRYPTION_KEY_ID.
    SSRF_ALLOW_LOCAL_URLS false Allow http:// and loopback provider URLs. Local development only (for example Ollama).
    ALLOW_PLATFORM_LLM_FALLBACK_DEFAULT true Whether an organization without credentials may use the platform default model
    PASSWORD_RESET_URL_BASE http://localhost:3001/reset-password Base of the set-password links the invite endpoint returns
    CORS_ORIGINS local origins Allowed browser origins
    LOG_LEVEL INFO Log verbosity (logs are structured JSON)

    Troubleshooting¶

    Symptom Cause and fix
    connection refused on port 8000 The API container is still migrating. Wait for docker compose ps to show it healthy.
    401 Invalid token on provisioning The service token was signed with a different JWT_SECRET_KEY than the API uses.
    403 Missing scopes: provision:... Mint the token with the scope named in the message.
    500 when creating an LLM credential LLM_CREDENTIAL_ENCRYPTION_KEY is not set on the API container.
    Port already in use Another process uses 8000, 5453, 6333 or 9000. Change the published port in docker-compose.yml.
