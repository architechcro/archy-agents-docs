    GET /api/v1/workflow-node-types¶

    List workflow node types

    Use case: the workflow editor and validators read the authoritative node type registry (data JSON Schemas, handles, connection rules, execution metadata).

    Auth: any valid bearer token (user or service, org or project scoped). The registry is global and contains no tenant data.

    GET /api/v1/orgs/{org_id}/projects/{project_id}/workflows/usage¶

    Get per-workflow usage counts

    Use case: dashboard ranking of which workflows run most often.

    Aggregates the workflow_runs table per workflow: total runs, succeeded, failed, and last run timestamp, ordered by total runs descending.

    Limitation: workflow_runs rows are only created by the async polling endpoint (POST .../workflows/{workflow_id}/runs). Synchronous /execute and SSE/NDJSON streaming executions are not counted, so these totals under-report overall usage.

    Auth: Bearer JWT; org_id and project_id must match token tenancy.

    Parameters

    Name In Type Required Description
    org_id path string (uuid) yes Organization id.
    project_id path string (uuid) yes Project id.
    since query string (date-time) no
    until query string (date-time) no
    limit query integer no (min 1, max 200, default 50)

    Example

    curl -N -X GET "$ARCHY_API_URL/api/v1/orgs/$ORG_ID/projects/$PROJECT_ID/workflows/usage" \
  -H "Authorization: Bearer $ARCHY_TOKEN"

    import os
import httpx

BASE_URL = os.environ["ARCHY_API_URL"]
HEADERS = {"Authorization": f"Bearer {os.environ['ARCHY_TOKEN']}"}
ORG_ID = "<org_id>"

with httpx.stream("GET", f"{BASE_URL}/api/v1/orgs/{ORG_ID}/projects/{PROJECT_ID}/workflows/usage", headers=HEADERS, timeout=None) as response:
    response.raise_for_status()
    for line in response.iter_lines():
        if line:
            print(line)

    POST /api/v1/orgs/{org_id}/projects/{project_id}/workflows/dialog/run¶

    Run dialog workflow (NDJSON stream)

    Use case: execute a dialog-style workflow and stream events as newline-delimited JSON (NDJSON).

    This is convenient for server-side orchestration where each line is an event object.

    Auth: Bearer JWT; org_id and project_id must match token tenancy.

    Parameters

    Name In Type Required Description
    org_id path string (uuid) yes Organization id.
    project_id path string (uuid) yes Project id.

    Request body (application/json, required)

    Field Type Required Description
    agent_a_id string (uuid) yes
    agent_b_id string (uuid) yes
    prompt string yes (min length 1)
    turns integer no (min 1.0, max 50.0, default 4)

    Schema: DialogRunRequest

    Example

    curl -N -X POST "$ARCHY_API_URL/api/v1/orgs/$ORG_ID/projects/$PROJECT_ID/workflows/dialog/run" \
  -H "Authorization: Bearer $ARCHY_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
  "agent_a_id": "70f485d6-7c9e-57c5-bf09-5f4a69e2421a",
  "agent_b_id": "0691da2d-43aa-562d-8ff4-9fdd5ef04c31",
  "prompt": "string"
}'

    import os
import httpx

BASE_URL = os.environ["ARCHY_API_URL"]
HEADERS = {"Authorization": f"Bearer {os.environ['ARCHY_TOKEN']}"}
ORG_ID = "<org_id>"
PROJECT_ID = "<project_id>"

payload = {
    "agent_a_id": "70f485d6-7c9e-57c5-bf09-5f4a69e2421a",
    "agent_b_id": "0691da2d-43aa-562d-8ff4-9fdd5ef04c31",
    "prompt": "string"
}

with httpx.stream("POST", f"{BASE_URL}/api/v1/orgs/{ORG_ID}/projects/{PROJECT_ID}/workflows/dialog/run", headers=HEADERS, json=payload, timeout=None) as response:
    response.raise_for_status()
    for line in response.iter_lines():
        if line:
            print(line)

    Responses

    Status Description Body

    POST /api/v1/orgs/{org_id}/workflows/{workflow_id}/execute¶

    Execute org-scoped workflow

    Execute an org-scoped workflow (project_id=NULL) on org-scoped agents and return the final output plus an audit trail. Org-scoped execution supports sequential/parallel workflow types.

    Auth: Bearer JWT; org_id must match token tenancy.

    Parameters

    Name In Type Required Description
    org_id path string (uuid) yes Organization id.
    workflow_id path string (uuid) yes Workflow id.
    project_id query string (uuid) no Project id.

    Request body (application/json, required)

    Field Type Required Description
    message string yes User input to execute the workflow with. (min length 1)
    session_id string (uuid) no Optional workflow session id. If omitted, a new session is created; if provided, the existing session is resumed.
    structured_output_schema object no Optional client-provided JSON Schema (limited subset) that is used to enforce structured output in a finalization step. The final structured payload is returned as structured_output when validation succeeds.
    structured_output_agent_id string (uuid) no Optional agent id to use as the structured-output finalizer. If omitted, the workflow may use config.structured_output_agent_id or a default agent.
    instructions_overlay string no Optional per-turn context injected before the user message. Used by interactive-orchestrator workflows to pass protocol, progress state, and template sections without persisting them in the workflow definition.
    knowledge_base_id_override string (uuid) no Optional knowledge base ID to use for RAG retrieval on this execution. Overrides the workflow config's knowledge_base_id if provided.
    inputs object no Optional workflow inputs: name -> value for the inputs the composite workflow declares. Defaults are applied and values are coerced to the declared type; unknown names, missing required inputs and type mismatches give a 422 WORKFLOW_INPUTS_INVALID. Templates read them as input.<name>. Values are recorded in the run trace (session history) unless the input is declared sensitive, which records ***.
    mcp_enabled boolean no Per-request MCP switch. Null keeps the agent configuration; false registers no MCP tools for this run. Not persisted.
    mcp_tool_allowlist array of string no Per-request MCP tool allowlist: only tools with these server-side names (without the server prefix, e.g. jira_get_issue) are registered for every agent in this run. Null keeps all tools. Not persisted.
