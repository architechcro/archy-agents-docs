    Conventions¶

    Rules that apply to every endpoint.

    Base URL and versioning¶

    Environment Base URL
    Hosted https://archy-agents.fly.dev
    Local http://localhost:8000

    All routes are under /api/v1. Within v1, treat responses as forward compatible: ignore fields and stream events you do not know. New optional request fields, endpoints and event types can appear at any time. The OAuth discovery documents live at /.well-known/... and /oauth/...; health probes at /health.

    The examples use two environment variables:

    export ARCHY_API_URL=https://archy-agents.fly.dev
export ARCHY_TOKEN="<bearer token>"

    Authentication¶

    Send Authorization: Bearer <token> on every request except health probes and OAuth discovery. Token types and how to get them: Authentication and tokens.

    Tenant scoping¶

    Resources belong to an organization and usually a project. Most routes carry both in the path:

    /api/v1/orgs/{org_id}/projects/{project_id}/...
    • The ids in the path must equal the tenant of the token, otherwise the API returns 403 Forbidden.
    • Organization-scoped resources use /api/v1/orgs/{org_id}/....
    • Some routes take the tenant from the token and accept org_id and project_id only as optional query parameters (for example /api/v1/agents/{agent_id}/query, /api/v1/llm-providers/...). A service token must supply them as query parameters on those routes.
    • Several older alias paths exist (for example /api/v1/agents/orgs/{org_id}/projects/{project_id}/agents/... and /api/v1/workflows/orgs/...). They behave like the canonical ones. Prefer the canonical /api/v1/orgs/{org_id}/projects/{project_id}/... form in new code.

    Data formats¶

    Topic Rule
    Content type application/json for bodies, multipart/form-data for file uploads
    Ids UUID strings (lowercase, hyphenated)
    Timestamps ISO 8601, UTC
    Unknown request fields Rejected for strictly validated objects (for example agent config); ignored elsewhere. Check the schema.
    Secrets Write-only. API keys, MCP headers and similar values are never returned.

    Errors¶

    Errors return JSON with a detail and, for server-generated errors, a request_id that matches the X-Request-ID response header.

    Status Body shape
    401, 403, 404, most 400 {"detail": "message", "request_id": "..."}
    422 {"detail": [{"type", "loc", "msg", "input"}]}
    Coded conflicts and workflow errors {"detail": {"code": "...", "message": "..."}}
    Invalid agent config (400) {"detail": {"message": "Invalid config", "errors": [...]}}

    See Errors, limits and practices for handling and retries.

    Pagination and filtering¶

    Collections that can grow take limit and offset query parameters. Filters are explicit query parameters documented on each endpoint.

    Idempotency¶

    Endpoint kind Behavior
    Provisioning PUT Idempotent upserts keyed by the id in the path
    PUT on resources Replaces the provided fields; agent config is replaced as a whole
    POST that creates Not idempotent; a retry creates a second resource
    DELETE Check the endpoint. Only the provisioning credential delete is documented as idempotent (it returns deleted: false for an absent credential).

    Streaming¶

    Format Content-Type Used by
    Server-Sent Events text/event-stream .../chat/stream, .../execute/stream
    NDJSON application/x-ndjson Knowledge base retrieval preview, dialog runs, orchestrator runs

    Streams report failures in-band after a 200 status. See Running and streaming.

    Rate limits and size limits¶

    • Authentication endpoints are rate limited per IP and per account (429 with Retry-After).
    • Document uploads are limited to 50 MB per file; artifacts to 25 MB by default.
    • Operators can configure additional limits per deployment.

    Headers¶

    Header Direction Purpose
    Authorization request Bearer token
    Content-Type request application/json or multipart/form-data
    X-Request-ID both Correlation id. Send your own or read the generated one.
    Retry-After response Seconds to wait after 429
    Cache-Control response private, max-age=300 on the workflow contract endpoints; no-cache on streams

    CORS¶

    Browser access is limited to the origins the operator configured (CORS_ORIGINS). Call the API from your backend unless you control the deployment, and never expose service tokens to a browser.
