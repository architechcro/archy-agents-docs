    Knowledge bases and RAG¶

    Create knowledge bases, ingest documents, index and query them.

    This page documents 30 endpoint(s). Replace $ARCHY_API_URL and $ARCHY_TOKEN as described in Conventions.

    Besides the responses listed for each endpoint, any endpoint can return 401 (missing or invalid token), 403 (wrong tenant, role or scope) and 404 (resource not found in your tenant). See Errors.

    GET /api/v1/rag/status¶

    RAG router status

    Use case: lightweight check that the RAG router is reachable.

    This does not validate dependency health; use /health/readiness for that.

    Authentication: none (public).

    Example

    curl -X GET "$ARCHY_API_URL/api/v1/rag/status"

    import os
import httpx

BASE_URL = os.environ["ARCHY_API_URL"]

response = httpx.request("GET", f"{BASE_URL}/api/v1/rag/status", timeout=60)
response.raise_for_status()
print(response.json())

    Responses

    Status Description Body
    200 Successful Response StatusResponse

    Example 200 response:

    {
  "status": "completed"
}

    POST /api/v1/orgs/{org_id}/projects/{project_id}/knowledge-bases¶

    Use case: create a new knowledge base (KB) within a project.

    Next steps: upload documents to the KB and call the indexing endpoint before querying.

    Auth: Bearer JWT; org_id and project_id must match token tenancy.

    Name In Type Required Description
    org_id path string (uuid) yes Organization id.
    project_id path string (uuid) yes Project id.

    Field Type Required Description

    description string no
    embedding_model string no
    vector_store_config object no

  -H "Authorization: Bearer $ARCHY_TOKEN" \

    POST /api/v1/orgs/{org_id}/projects/{project_id}/knowledge-bases/{kb_id}/query¶

    Query knowledge base

    Use case: retrieve the top-k most relevant chunks from a knowledge base for a query.

    Typical flow: upload → index → query; then pass retrieved context into agent/workflow execution.

    Auth: Bearer JWT; org_id and project_id must match token tenancy.

    Parameters

    Name In Type Required Description
    org_id path string (uuid) yes Organization id.
    project_id path string (uuid) yes Project id.
    kb_id path string (uuid) yes Knowledge base id.

    Request body (application/json, required)

    Field Type Required Description
    query string yes (min length 1, max length 20000)
    top_k integer no (min 1.0, max 50.0, default 5)
    retrieval_strategy enum: hybrid, vector, graph no Retrieval strategy to use when querying the knowledge base. - hybrid (default): combines vector similarity and lexical scores (standard RAG). - vector: uses only the vector similarity score. - graph: KAG/GraphRAG-style retrieval that expands the initial vector results using entity overlap extracted from the query and top-k chunks, enabling multi-hop reasoning over entity relationships. (default "hybrid")

    Schema: RAGQueryRequest
