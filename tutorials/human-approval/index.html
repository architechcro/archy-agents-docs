    Human approval checkpoint¶

    Some steps should not run until a person agrees: sending an email, publishing content, spending money. A checkpoint node pauses a composite workflow, shows a question, and continues when someone answers.

    sequenceDiagram
    autonumber
    participant App as Your app
    participant A as Archy API
    participant H as Approver
    App->>A: POST .../workflows/{id}/execute {inputs}
    A-->>App: status awaiting_input, pending_input, session_id
    App->>H: show the draft and the question
    H-->>App: approve or request changes
    App->>A: POST .../sessions/{session_id}/resume {answer}
    A-->>App: status completed, output

    Prepare: the Quickstart done and the archy.py helper from the support assistant tutorial.

    1. Build the workflow¶

    The workflow drafts a customer reply, pauses for approval, then finalizes the text using the approver's answer. It also declares a sensitive input: the customer's email address is masked in stored traces and must be sent again when the run resumes.

    # approval_workflow.py
from archy import SCOPE, client


def make_agent(name: str, prompt: str) -> str:
    r = client.post(f"{SCOPE}/agents", json={"name": name, "config": {"sys_prompt": prompt}})
    r.raise_for_status()
    return r.json()["id"]


drafter = make_agent("reply-drafter", "You draft short, polite replies to customer tickets.")
sender = make_agent("reply-finalizer", "You finalize a reply using the reviewer's instructions. Return only the final text.")

definition = {
    "version": 2,
    "inputs": [
        {"name": "ticket", "type": "string", "required": True},
        {"name": "customer_email", "type": "string", "required": True, "sensitive": True},
    ],
    "graph": {
        "nodes": [
            {"id": "s", "type": "start", "data": {}},
            {"id": "a", "type": "agent", "data": {
                "name": "draft", "agentId": drafter,
                "prompt": "Draft a reply to this ticket:\n{{input.ticket}}"}},
            {"id": "k", "type": "checkpoint", "data": {
                "name": "approval",
                "prompt": "Approve this draft, or tell me what to change:\n\n{{nodes.draft.output}}"}},
            {"id": "b", "type": "agent", "data": {
                "name": "final", "agentId": sender,
                "prompt": "Draft:\n{{nodes.draft.output}}\n\nReviewer says: {{nodes.approval.output}}\nCustomer address: {{input.customer_email}}\nWrite the final reply."}},
            {"id": "e", "type": "end", "data": {}},
        ],
        "edges": [
            {"id": "e1", "source": "s", "target": "a"},
            {"id": "e2", "source": "a", "target": "k"},
            {"id": "e3", "source": "k", "target": "b"},
            {"id": "e4", "source": "b", "target": "e"},
        ],
    },
}

workflow = client.post(f"{SCOPE}/workflows", json={"name": "reply-with-approval", "type": "composite", "config": definition})
workflow.raise_for_status()
workflow_id = workflow.json()["id"]
report = client.post(f"{SCOPE}/workflows/{workflow_id}/validate", json={}).json()
print(workflow_id, "valid" if report["valid"] else report["errors"])

    Points to notice:

    • The checkpoint prompt is a template. It may read earlier nodes (nodes.draft.output) but not a sensitive input: a checkpoint prompt that reads one raises the CHECKPOINT_PROMPT_SENSITIVE_INPUT warning because stored prompts show it masked.
    • A checkpoint must have an outgoing connection; otherwise validation warns DANGLING_CHECKPOINT.
    • The checkpoint node completes with the answer as its output, so later nodes read it as {{nodes.approval.output}} (the checkpoint's name is approval).

    2. Start a run and detect the pause¶

    curl -s -X POST "$BASE/workflows/$WORKFLOW_ID/execute" \
  -H "Authorization: Bearer $ARCHY_TOKEN" -H "Content-Type: application/json" \
  -d '{"message": "Handle this ticket", "inputs": {"ticket": "My invoice shows the wrong VAT number.", "customer_email": "ada@example.com"}}'

    The response reports the pause:

    {
  "session_id": "5c9ef9bb-4dd5-4c14-b2ac-0f93f4b5f4d1",
  "output": "Approve this draft, or tell me what to change:\n\nHello, thank you for ...",
  "status": "awaiting_input",
  "pending_input": {
    "status": "awaiting_input",
    "question": "Approve this draft, or tell me what to change:\n\nHello, thank you for ...",
    "node_id": "k",
    "node_name": "approval",
    "iteration": null
  },
  "audit": [],
  "error": null
}

    Store the session_id. It identifies the paused run. iteration is set only when the checkpoint sits inside a loop.

    Use an asynchronous run for the same flow when your caller cannot wait: GET .../runs/{run_id} then returns status: "awaiting_input" and the session_id.

    3. Resume with the answer¶

    curl -s -X POST "$BASE/workflows/$WORKFLOW_ID/sessions/$SESSION_ID/resume" \
  -H "Authorization: Bearer $ARCHY_TOKEN" -H "Content-Type: application/json" \
  -d '{"answer": "Approved. Add an apology for the delay.", "inputs": {"customer_email": "ada@example.com"}}'
    • answer is required, 1 to 32,768 characters.
    • Send every sensitive input again in inputs: they are deliberately not stored with the paused run. Other inputs are restored automatically. Sending a non-sensitive input returns 422 (WORKFLOW_INPUTS_INVALID).
    • Resuming a run that is not paused, was cancelled, or has expired returns an error and never runs twice.

    To reject the draft entirely:

    curl -s -X POST "$BASE/workflows/$WORKFLOW_ID/sessions/$SESSION_ID/cancel" -H "Authorization: Bearer $ARCHY_TOKEN"
# {"session_id": "...", "status": "cancelled"}

    4. A small approval service¶

    Put the pause behind your own UI. This backend keeps a list of pending approvals and resumes the run when a person decides.

    # approvals.py
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel

from archy import SCOPE, client

app = FastAPI()
pending: dict[str, dict] = {}  # approval id -> run info; use a database in production


class Ticket(BaseModel):
    ticket: str
    customer_email: str


@app.post("/tickets")
def start(t: Ticket, workflow_id: str):
    r = client.post(
        f"{SCOPE}/workflows/{workflow_id}/execute",
        json={"message": "Handle this ticket", "inputs": t.model_dump()},
    )
    r.raise_for_status()
    run = r.json()
    if run["status"] == "awaiting_input":
        pending[run["session_id"]] = {"workflow_id": workflow_id, "email": t.customer_email, "draft": run["output"]}
        return {"state": "needs_approval", "approval_id": run["session_id"], "draft": run["output"]}
    return {"state": "done", "output": run["output"]}


class Decision(BaseModel):
    approve: bool
    comment: str = ""


@app.post("/approvals/{approval_id}")
def decide(approval_id: str, d: Decision):
    info = pending.pop(approval_id, None)
    if info is None:
        raise HTTPException(404, "unknown approval")
    base = f"{SCOPE}/workflows/{info['workflow_id']}/sessions/{approval_id}"
    if not d.approve and not d.comment:
        client.post(f"{base}/cancel").raise_for_status()
        return {"state": "cancelled"}
    r = client.post(
        f"{base}/resume",
        json={"answer": d.comment or "Approved.", "inputs": {"customer_email": info["email"]}},
    )
    r.raise_for_status()
    return {"state": "done", "output": r.json()["output"]}

    5. Things to plan for¶

    Topic Guidance
    Expiry Paused runs expire (7 days by default). An expired checkpoint reports failed when resumed. Remind approvers or cancel stale ones.
    Who can resume Anyone with a token for the project can call resume. Enforce who may approve in your own application before you call it.
    Audit The session trace records the question and the answer. Use GET .../workflows/{id}/sessions/{session_id} to show the history.
    Loops A checkpoint inside a loop pauses on every iteration; pending_input.iteration says which one.
    Secrets Keep secrets out of checkpoint prompts. Use sensitive inputs and resend them on resume.
    Idempotency Two simultaneous resumes cannot both run: one holds a claim and the other receives an error. Retry only after reading the session status.
    Cost on resume Nodes that already finished are replayed from their saved results without calling the model again.
