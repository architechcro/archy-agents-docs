    Support assistant with RAG¶

    You will build a customer support assistant that answers from your documentation, check its quality with a small test set, and expose it through a streaming endpoint in your own backend.

    flowchart LR
    DOCS[Docs folder] -->|ingest.py| KB[(Knowledge base)]
    KB --> AG[Support agent]
    GOLD[questions.json] -->|evaluate.py| AG
    UI[Your web app] -->|/chat| BE[Your backend]
    BE -->|SSE| AG

    Prepare: the Quickstart done, a folder docs/ with a few PDF, Markdown or Word files, and these variables:

    export ARCHY_API_URL=http://localhost:8000
export ARCHY_TOKEN="<admin user token>"
export ORG_ID="<org id>" PROJECT_ID="<project id>"
pip install httpx

    1. A small client¶

    All scripts share one helper.

    # archy.py
import os

import httpx

BASE_URL = os.environ["ARCHY_API_URL"]
ORG_ID, PROJECT_ID = os.environ["ORG_ID"], os.environ["PROJECT_ID"]
SCOPE = f"/api/v1/orgs/{ORG_ID}/projects/{PROJECT_ID}"

client = httpx.Client(
    base_url=BASE_URL,
    headers={"Authorization": f"Bearer {os.environ['ARCHY_TOKEN']}"},
    timeout=120,
)

    2. Create the knowledge base and ingest¶

    # ingest.py
import pathlib
import sys
import time

from archy import SCOPE, client

SUPPORTED = {".pdf", ".md", ".txt", ".docx", ".html", ".json", ".xlsx", ".pptx"}

kb = client.post(f"{SCOPE}/knowledge-bases", json={"name": "support-docs", "description": "Product documentation"})
kb.raise_for_status()
kb_id = kb.json()["id"]
print("knowledge base", kb_id)

files = [p for p in pathlib.Path(sys.argv[1]).rglob("*") if p.suffix.lower() in SUPPORTED]
for start in range(0, len(files), 10):  # upload in batches of 10
    batch = files[start : start + 10]
    response = client.post(
        f"{SCOPE}/knowledge-bases/{kb_id}/documents/upload",
        files=[("files", (p.name, p.read_bytes())) for p in batch],
    )
    response.raise_for_status()
    print(f"uploaded {len(batch)} files")

while True:
    stats = client.get(f"{SCOPE}/knowledge-bases/{kb_id}/stats").json()
    print(stats)
    if stats["indexing_total"] == 0:
        break
    time.sleep(3)

if stats["indexed_total"] < stats["files_total"]:
    failed = [d for d in client.get(f"{SCOPE}/knowledge-bases/{kb_id}/documents").json() if d["status"] == "failed"]
    print("failed documents:", [d["filename"] for d in failed])

    python ingest.py ./docs

    3. Check retrieval before you build the agent¶

    Good answers need the right chunks. Write 10 to 20 real questions, each with a phrase that must appear in the retrieved text.

    [
  {"q": "How long do I have to ask for a refund?", "expect": "30 days"},
  {"q": "What are the support hours?", "expect": "08:00"},
  {"q": "Do enterprise customers get a named contact?", "expect": "named contact"}
]

    # check_retrieval.py
import json
import sys

from archy import SCOPE, client

kb_id = sys.argv[1]
cases = json.load(open("questions.json"))
misses = 0
for case in cases:
    r = client.post(f"{SCOPE}/knowledge-bases/{kb_id}/query", json={"query": case["q"], "top_k": 5})
    r.raise_for_status()
    text = " ".join(hit["content"] for hit in r.json()["results"]).lower()
    ok = case["expect"].lower() in text
    misses += not ok
    print("PASS" if ok else "MISS", "-", case["q"])
print(f"{len(cases) - misses}/{len(cases)} retrieved")

    If questions miss, try "retrieval_strategy": "vector" or "graph" for multi-hop questions, split very long documents, or add the missing content.

    4. Create the agent¶

    # create_agent.py
import sys

from archy import SCOPE, client

PROMPT = """You are the support assistant for Acme.
Answer only from the knowledge base. If the answer is not there, say you do not know and offer to
connect the customer with a person. Be concise: at most four sentences. Never invent prices or dates."""

agent = client.post(
    f"{SCOPE}/agents",
    json={
        "name": "support-assistant",
        "description": "Answers customer questions from the product docs",
        "config": {
            "sys_prompt": PROMPT,
            "knowledge_base_id": sys.argv[1],
            "knowledge_base_top_k": 5,
            "temperature": 0.1,
            "max_tokens": 600,
            "memory": {"mode": "buffer", "window_messages": 10},
        },
    },
)
agent.raise_for_status()
print(agent.json()["id"])

    The agent runs on the organization's attached model (LLM providers).

    5. Evaluate end to end¶

    Reuse the same questions, but ask the agent and check the answer text. Use a fresh session per question so one answer cannot leak into the next.

    # evaluate.py
import json
import sys

from archy import client

agent_id = sys.argv[1]
cases = json.load(open("questions.json"))
passed = 0
for case in cases:
    r = client.post(f"/api/v1/agents/{agent_id}/query", json={"message": case["q"]})
    r.raise_for_status()
    answer = r.json()["output"]
    ok = case["expect"].lower() in answer.lower()
    passed += ok
    print("PASS" if ok else "FAIL", "-", case["q"], "->", answer[:100].replace("\n", " "))
print(f"{passed}/{len(cases)} passed")

    Run it after every prompt or content change. Keep the questions in version control; they are your regression suite.

    6. Expose it through your backend¶

    Browsers must never see an Archy token. Your backend authenticates the end user, calls Archy, and relays the stream. This FastAPI endpoint keeps one Archy session per conversation.

    # app.py
import json
import os

import httpx
from fastapi import FastAPI
from fastapi.responses import StreamingResponse
from pydantic import BaseModel

BASE = os.environ["ARCHY_API_URL"]
SCOPE = f"/api/v1/orgs/{os.environ['ORG_ID']}/projects/{os.environ['PROJECT_ID']}"
AGENT_ID = os.environ["AGENT_ID"]
HEADERS = {"Authorization": f"Bearer {os.environ['ARCHY_TOKEN']}"}

app = FastAPI()
sessions: dict[str, str] = {}  # your user or conversation id -> Archy session_id; use a database in production


class ChatRequest(BaseModel):
    conversation_id: str
    message: str


@app.post("/chat")
async def chat(req: ChatRequest) -> StreamingResponse:
    body = {"message": req.message}
    if req.conversation_id in sessions:
        body["session_id"] = sessions[req.conversation_id]

    async def relay():
        async with httpx.AsyncClient(base_url=BASE, headers=HEADERS, timeout=None) as client:
            async with client.stream("POST", f"{SCOPE}/agents/{AGENT_ID}/chat/stream", json=body) as upstream:
                upstream.raise_for_status()
                event = ""
                async for line in upstream.aiter_lines():
                    if line.startswith("event:"):
                        event = line[6:].strip()
                    elif line.startswith("data:"):
                        data = json.loads(line[5:].lstrip())
                        if event == "start":
                            sessions[req.conversation_id] = data["session_id"]
                        elif event == "delta":
                            yield f"data: {json.dumps({'text': data['delta']})}\n\n"
                        elif event == "error":
                            yield f"data: {json.dumps({'error': 'The assistant is unavailable.'})}\n\n"
                yield "data: [DONE]\n\n"

    return StreamingResponse(relay(), media_type="text/event-stream", headers={"Cache-Control": "no-cache"})

    In the browser, read it with fetch:

    const res = await fetch("/chat", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ conversation_id: "c-1", message: "What is the refund window?" }),
});
const reader = res.body.pipeThrough(new TextDecoderStream()).getReader();
for (;;) {
  const { value, done } = await reader.read();
  if (done) break;
  for (const line of value.split("\n")) {
    if (line.startsWith("data: ") && line !== "data: [DONE]") {
      output.textContent += JSON.parse(line.slice(6)).text ?? "";
    }
  }
}

    Do not leak internal errors

    The relay turns Archy's error event into a generic message. Log the original detail and the request_id on your side.

    7. Operate it¶

    • Update content: delete the old document (DELETE .../documents/{doc}), upload the new one, and wait for indexing. Re-run check_retrieval.py.
    • Change behavior: update the agent's prompt with PUT (send the whole config) and re-run evaluate.py.
    • See what happened: GET .../sessions and GET .../sessions/{id}/activity show conversations and retrievals.
    • Track cost: GET .../token-usage/aggregations?group_by=agent (usage).

    What you learned¶

    You created and indexed a knowledge base, measured retrieval, configured a grounded agent, regression-tested it and streamed it safely through your backend.
